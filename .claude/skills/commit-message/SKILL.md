## Формат

<тип>(<область>): <что сделано>

Типы: например: feat, fix, docs, refactor, test, chore

## Соглашение по commit-message

На проекте мы используем соглашение совместимое с Conventional Commits.

Сообщения коммитов должны быть следующей структуры:

Формат:
`<тип>(контекст): <опционально JIRA-ID> <описание>`

1.  Типы изменений

Коммит должен начинаться с типа, который является существительным:

_Публикуемые в changelog изменения._ - должны кратко и ясно описывать изменение, но с value для для конечный пользователей данной библиотеки компонентов.

| Тип               | Описание                |
| ----------------- | ----------------------- |
| `feat`            | Новая функциональность  |
| `fix`             | Исправление ошибки      |
| `BREAKING CHANGE` | Критические изменения   |
| `refactor`        | Рефакторинг кода        |
| `test`            | Изменения тестов        |
| `docs`            | Обновление документации |
| `ci`              | Изменения CI/CD         |

_Непубликуемые (nfp - not for publish) в changelog изменения._

| Тип                   | Описание                |
| --------------------- | ----------------------- |
| `nfp-feat`            | Новая функциональность  |
| `nfp-fix`             | Исправление ошибки      |
| `nfp-BREAKING CHANGE` | Критические изменения   |
| `nfp-refactor`        | Рефакторинг кода        |
| `nfp-test`            | Изменения тестов        |
| `nfp-docs`            | Обновление документации |
| `nfp-ci`              | Изменения CI/CD         |

2.  Структура

`<тип>(контекст): <опционально JIRA-ID> <описание>`

- **контекст**: описывает часть кодовой базы, которую затронул коммит, записывается в круглых скобках (`ModalDF`, `TableCanvas`)
- **опционально JIRA-ID**: опционально. Номер задачи в [jira](https://jira.dddddd.ru/secure/RapidBoard.jspa)
- **описание**: кратко на русском с маленькой буквы

## Правила

- Первая строка — не длиннее 72 символов.
- Используй повелительное наклонение: «добавить», «исправить», «убрать».
- Если изменение затрагивает несколько областей — раздели на отдельные коммиты.

## Стиль формулировки

**Важно:** Сообщение коммита должно быть безличным (без местоимений 1-го лица — "я", "мы", "добавил", "сделал", "оптимизировал").

Используйте глаголы в повелительном наклонении или страдательные причастия прошедшего времени:

- ✅ **Правильно (причастия):** "добавлен новый функционал", "исправлена ошибка", "обновлена документация"
- ❌ **Неправильно:** "добавил новый функционал", "исправил ошибку", "обновил документацию"

## Примеры

feat(Table): добавлен новый функционал массовых действий - MassActionPanel

nfp-docs(DrawerDF): в story поправлены отступы между основными блоками

## Пиши в формате что сделано, а не что сделать

- Неправильно: "nfp-docs(commit-message): обновить описание скилла для закоммитивания изменений"
- Правильно: "nfp-docs(commit-message): обновлено описание скилла для закоммитивания изменений"
