# Сообщение коммита

Формат проверяет хук `scripts/husky-commit/check-commit-msg.js`; при
расхождении прав хук прав, а не этот файл.

## Заголовок

```
<тип>(<контекст>): <опционально JIRA-ID> <описание>
```

**Тип** — строго один из списка, другие (`chore`, `style`, `perf`) хук
отклонит.

| Публикуется в changelog | Не публикуется | Когда                  |
| ----------------------- | -------------- | ---------------------- |
| `feat`                  | `nfp-feat`     | новая функциональность |
| `fix`                   | `nfp-fix`      | исправление ошибки     |
| `refactor`              | `nfp-refactor` | рефакторинг            |
| `test`                  | `nfp-test`     | тесты                  |
| `docs`                  | `nfp-docs`     | документация           |
| `ci`                    | `nfp-ci`       | CI/CD, сборка, хуки    |

**Публикуемый или `nfp-`?** Публикуемый — если изменение заметно потребителю
библиотеки: компонент, проп, поведение, вёрстка, экспорт, типы. `nfp-` —
внутреннее: stories, MDX, тесты, CI, скрипты, инструкции агентов, рефакторинг
без изменения поведения. Changelog читают разработчики приложений: публикуемый
заголовок должен объяснять им пользу.

**Контекст** — компонент или область: `ModalDF`, `TableCanvas`, `prettier`,
`screenshots`.

**Описание** — по-русски, с маленькой буквы, безлично, причастием прошедшего
времени: «добавлен», «исправлена», «убран». Не «добавил», не «добавить».
Заголовок — не длиннее 72 символов, без точки в конце.

**Таблицы.** В контексте `TableCanvas` и `TableGlide` описание начинается с
фичи или Canvas-элемента, которого касается правка, затем тире и суть с
маленькой буквы. Иначе в changelog десятки строк `fix(TableCanvas): …` подряд, и
что изменилось, видно только в конце строки. Имя пишется как в коде и Storybook
(исключение из правила «с маленькой буквы»): по нему коммиты фичи находятся в
истории и совпадают с разделами документации и MCP.

- фича — раздел story `TableCanvas.<Фича>` (папки в
  `packages/storybook/src/stories/TableCanvas/`): `Editing`, `ColumnResize`,
  `CellsMerging`, `ContextMenu`, `SummaryRows`;
- элемент — имя из API: `Canvas.Badge`, `Canvas.Text`, `Canvas.Button`;
- несколько фич — через запятую; общее для всей таблицы (ядро отрисовки,
  производительность) — `Core`.

## Тело (необязательно)

После пустой строки: зачем сделано и что важно знать, а не пересказ diff.

Не заканчивай строку двоеточием: хук `prepare-commit-msg` склеивает строку,
оканчивающуюся на `:`, со следующей.

## Ломающее изменение

Не тип в заголовке, а отдельная строка в теле, строго в формате
`BREAKING CHANGE: <описание>` — иначе lerna не поднимет major-версию:

```
feat(Table): убран deprecated-проп colorScheme

BREAKING CHANGE: проп colorScheme больше не поддерживается, используйте theme
```

Такой коммит появляется только в major-релизе и удаляет то, что раньше было
помечено `@deprecated` (процесс — раздел «Ломающие изменения» в `AGENTS.md`).
Коммит, который помечает API устаревшим, — обычный `feat` без
`BREAKING CHANGE`.

## Правила

- Один коммит — одна логическая единица. Разные компоненты или несвязанные
  правки — разные коммиты.
- Трейлеры (`Co-Authored-By` и т. п.) — по правилам пользователя и агента.

## Примеры

```
feat(Table): добавлен функционал массовых действий MassActionPanel
fix(DrawerDF): исправлено закрытие по Esc при открытом Dropdown
nfp-docs(DrawerDF): в story поправлены отступы между основными блоками
nfp-ci(screenshots): автозапуск на PR в develop
fix(TableCanvas): Canvas.Badge — добавлено многоточие для длинного текста
feat(TableCanvas): ColumnResize — линия при изменении ширины колонки
fix(TableCanvas): CellsMerging, Editing — рамка редактора обводит всю ячейку
```
