## Особенности проекта

- **Тип**: UI-библиотека (React 18 + TypeScript + styled-components)
- **Контекст**: 100+ переиспользуемых компонентов, 135+ Storybook-историй
- **Критерий**: безопасность компонентов, их интеграций и утилит

## Что проверить

### 1. XSS-векторы в компонентах

- `dangerouslySetInnerHTML` — только с валидацией/экранированием
- `eval()` и `new Function()` — строго запрещены (ESLint: error)
- Сторис-файлы: проверить отсутствие `eval()` в примерах
- Динамические идентификаторы (`data-testid`, `aria-*`): валидация входных значений

### 2. Инъекции в утилитах

- `bubble()`, `eventBus.emit()` — валидация событий ( whitelisting)
- `clickStream.sendEvent()` — экранирование payload
- `generateTraceId()` — безопасная генерация ID (не user-controlled)

### 3. Хардкод секретов

- Пароли, API-ключи, токены в:
  - компонентах (`*.tsx`/`*.ts`)
  - утилитах (`utils/*.ts`)
  - конфигах (`.storybook/*.ts`)
  - Storybook-файдах (`*.stories.tsx`)
- **Исключение**: тестовые фейковые данные в storybook (не продакшн)

### 4. Styled-components уязвимости

- Интерполяция CSS-значений: валидация/whitelisting
- `css` prop с user input — экранирование
- Динамические классы/атрибуты без санитизации

### 5. react-hook-form интеграции

- Правила валидации (Zod/Schema): проверка на path traversal
- `controller/renderProps` — санитизация value/onChange

### 6. Зависимости

- `@salutejs/sdds-finai` (базовые компоненты)
- Проверить `package.json` на устаревшие/уязвимые версии
- Peer dependencies: совместимость React >=17, styled-components

### 7. Storybook экспозиция

- Сторис с реальными API-вызовами — заменить на моки
- Публичные примеры: нет реальных токенов/секретов
- `hideInSidebar` теги для sensitive компонентов

## Формат отчёта

```markdown
## [Уровень: HIGH/MEDIUM/LOW]

**Где**: `path/to/file.tsx:12`
**Что**: краткое описание
**Последствия**: потенциальный ущерб
**Исправление**: конкретные действия (код/паттерн)
```

## Примечания

- Для компонентов форм: проверить валидацию Zod/Schema
- Для TableCanvas/react-data-grid: проверить колонки/cell-renderers на XSS
- Использовать `mergeRefs` правильно (не терять ref-цепочки)
- Дизайн-токены (`getTokenValue`) — безопасны, не требуют санитизации
