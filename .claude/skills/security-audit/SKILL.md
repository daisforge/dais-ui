# Аудит безопасности

`@daisforge/ui` выполняется в приложениях с данными пользователей и
публикуется в npm. Главные риски — XSS через пропсы и рендеры, утечка данных в
аналитику и логи, компрометация публикации или CI. Отчёт — только о
подтверждённых проблемах со сценарием атаки.

## Код ui-kit

- **HTML из данных:** `dangerouslySetInnerHTML`, `innerHTML`,
  `insertAdjacentHTML`, `document.write`. Значение может прийти от
  пользователя приложения? Тогда нужна санитизация или рендер текстом.
- **URL:** `href`, `src`, `window.open`, `location` из пропсов — нет ли
  `javascript:`/`data:` схем; у `target="_blank"` есть `rel="noopener"`.
- **Динамический код:** `eval`, `new Function`, строковый `setTimeout`.
- **Canvas и таблицы:** рендеры ячеек, тултипы, оверлеи `TableCanvas` —
  пользовательские строки выводятся как текст, а не как HTML.
- **styled-components:** интерполяция пользовательской строки в CSS
  (`url(...)`, произвольные свойства) позволяет внедрить стили — значения
  должны быть из ограниченного набора.
- **Данные наружу:** `clickStream`, `eventBus`, логгер `TableCanvas`,
  `generateTraceId` — не уходят ли значения полей, персональные данные, токены.
  `postMessage` — с проверкой `origin`.
- **Хранилища:** `localStorage`/`sessionStorage` — не пишутся ли туда
  чувствительные данные.

## Storybook и скрипты

- В stories, MSW-моках и фикстурах нет реальных токенов, URL внутренних
  сервисов и персональных данных — Storybook публичный.
- Скрипты (`scripts/`, `generators/`): `execSync`/`spawn` с подстановкой
  внешних строк — инъекция команд; пути из аргументов — выход за пределы
  репозитория.

## Зависимости и публикация

- Новые или обновлённые зависимости: нужны ли они, известный ли пакет,
  нет ли опечатки в имени, нет ли `postinstall`. `npm audit --omit=dev` — для
  runtime-зависимостей ui-kit.
- `package.json` пакетов: `files`/`.npmignore` не публикуют лишнего (`.env`,
  тесты, исходники с секретами).

## GitHub Actions

- `pull_request_target` и `workflow_run` с checkout кода PR — выполнение
  чужого кода с секретами.
- `${{ github.event.* }}` (заголовок PR, имя ветки) прямо в `run:` — инъекция
  команд; значения передаются через `env:`.
- `permissions:` — минимальные; `id-token: write` — только в публикации.
- Сторонние actions закреплены версией или SHA.
- Публикация в npm (`publish-npm.yml`) — через OIDC Trusted Publishing, без
  долгоживущих токенов.

## Формат отчёта

```markdown
### [HIGH | MEDIUM | LOW] Краткая суть

`path/to/file.tsx:12`
**Сценарий:** кто и как это эксплуатирует, что получает.
**Исправление:** конкретное изменение.
```

Если проблем не найдено — так и напиши, с перечнем того, что проверено.
