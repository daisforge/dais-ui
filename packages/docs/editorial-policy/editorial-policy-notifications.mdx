# 4.6. Уведомления и тосты

Раздел описывает, как писать тексты уведомлений и тостов на платформе {{Название}}.

> **⚠️ Основное правило:** если нужно обозначить результат **целевого действия** — используйте **уведомление**. В остальных случаях — **тост**.

Примеры:

- Результат создания сущности — уведомление «[Сущность] создана» (это целевое действие при создании сущности).
- Результат обновления таблицы — тост «Обновлено» (техническое оповещение, не целевое действие).

---

## Уведомление

Шаблоны текстов уведомлений созданы на основе кейсов, которые часто используются в продуктах платформы. Названия сущностей можно менять под свой продукт.

Пример: ваш кейс — распоряжение успешно отозвано. Шаблон: «[Сущность] отозвана». Итоговый текст: «Распоряжение отозвано».

> **💡 Подсказка:** если на странице нет подходящего шаблона для вашего кейса — напишите редактору, чтобы вместе продумать текст уведомления.

### Успешное действие: шаблоны текста

> **⚠️ Важно:** в тексте уведомлений **не пишем слово «успешно»** — рядом используется зелёная иконка-галочка, UI-элементов достаточно.

| Кейс | Возможный текст уведомления |
|---|---|
| Действие выполнено успешно | Изменения сохранены / Уведомления включены / Задача выполнена / Файл загружен / [Сущность] отозвана / [Сущность] переведена в архив / [Сущность] удалена |
| Успешное действие с определённым количеством сущностей | Удалено оценок: 3 / Сохранено оценок: 3 |

### Ошибка: шаблоны текста

| Кейс | Возможный текст уведомления |
|---|---|
| Произошла ошибка системы (может помочь перезагрузка страницы и/или повтор действия) | Не удалось [выполнить действие: загрузить, сохранить и т.п. с сущностью]. Обновите страницу и попробуйте снова |
| Произошла ошибка системы (может помочь перезагрузка и/или повтор) | Не удалось [выполнить действие] с сущностью. Попробуйте снова |
| При загрузке файлов система обнаружила и подсветила ошибки — нужно поправить и повторить | Не удалось загрузить: обнаружены ошибки. Исправьте их и попробуйте снова |
| Пользователь пытается создать дубликат сущности | Такая [Сущность] уже существует. Выберите другой тип или год [параметр или сущность, которые решают проблему] |
| Система не смогла сохранить данные — они не соответствуют правилам валидации | Не удалось сохранить. Подробности смотрите в логе ошибок |

> **🔗 См. также:** [Ошибки]({{Anchor editorial-policy-errors#Основные правила}}) (4.2) — общие правила текстов ошибок и шаблоны для экранов ошибок (HTTP-коды) и контекстных ошибок в полях.

### Предупреждения: шаблоны текста

| Кейс | Возможный текст уведомления |
|---|---|
| Не выбраны сущности для сравнения | Выберите 2 [сущности] для сравнения / Выберите хотя бы 2 [сущности] для сравнения |
| Выбрано больше сущностей, чем нужно | Можно отправить только один дистрибутив за раз |
| Действие выполнено только для части сущностей, для остальных невозможно | [Сущность] в статусах «На согласовании» и «Готово» не были перемещены в архив |
| Пользователь выбрал объединённую сущность вместо необъединённых | Выберите необъединённые [сущности] |

## Тост

Тост — небольшое и более техническое уведомление платформы. Обычно находится на экране около 5 секунд, потом исчезает. Чтобы пользователь успевал его считать — используем **максимально короткие тексты**. В негативном тосте используем слово «Ошибка».

### Тексты для тостов

**Успех:**

- Сохранено
- Скопировано
- Синхронизировано / Обновлено

> **💡 Подсказка:** предпочтительный вариант — «Обновлено». «Синхронизировано» — более техническое и сложное слово.

**Неуспех:**

- Ошибка. Попробуйте снова

## FAQ

**Q: Когда использовать уведомление, а когда тост?**
A: Уведомление — для результата целевого действия (например, «Файл загружен»). Тост — для технических оповещений (например, «Обновлено»). Подробнее — раздел [Основное правило]({{Anchor 4.6. Уведомления и тосты}}).

**Q: Можно ли писать «успешно» в уведомлении об успехе?**
A: Нет — рядом есть зелёная иконка-галочка, UI-элементов достаточно. Подробнее — раздел [Успешное действие]({{Anchor Успешное действие: шаблоны текста}}).

**Q: Как написать текст уведомления для своего кейса?**
A: Возьмите подходящий шаблон и замените название сущности под свой продукт (например, шаблон «[Сущность] отозвана» → «Распоряжение отозвано»). Если шаблона нет — напишите редактору. Подробнее — раздел [Уведомление]({{Anchor Уведомление}}).

**Q: Каким должен быть текст тоста?**
A: Максимально коротким — тост висит ~5 секунд. Успех: «Сохранено», «Обновлено». Неуспех: «Ошибка. Попробуйте снова». Подробнее — раздел [Тексты для тостов]({{Anchor Тексты для тостов}}).

**Q: «Синхронизировано» или «Обновлено» в тосте?**
A: Предпочтительно «Обновлено» — «Синхронизировано» более техническое и сложное слово. Подробнее — раздел [Тексты для тостов]({{Anchor Тексты для тостов}}).

**Q: Как написать текст ошибки в уведомлении?**
A: По шаблонам: «Не удалось [действие]. Обновите страницу и попробуйте снова» и т.п. Общие правила текстов ошибок — в разделе [Ошибки]({{Anchor editorial-policy-errors#Основные правила}}) (4.2).

**Q: Чем отличается уведомление об ошибке от тоста об ошибке?**
A: Уведомление об ошибке подробнее (что произошло + что делать), тост — максимально короткий («Ошибка. Попробуйте снова»). Уведомление — для результата целевого действия, тост — для технических оповещений.
