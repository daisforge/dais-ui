# Toast

Временное, неблокируемое уведомление, которое появляется на короткое время, чтобы предоставить пользователю обратную связь. Toast является кратким сообщением о статусе совершённого пользователем действия: не блокирует взаимодействие, не требует обязательного закрытия и не может нести в себе дополнительных действий.

Визуал: {{Pixso URL Toast Doc Block 1}}

---

## Когда использовать

Тост — для коротких технических оповещений о статусе, которые не являются результатом целевого действия пользователя. Типовые сценарии: «Сохранено», «Обновлено», «Скопировано», «Синхронизировано», «Удалено», «Вы перешли в режим редактирования», «Вы перешли в режим просмотра», «Ошибка. Попробуйте снова».

Если сообщение — это результат целевого действия пользователя или требует кнопки действия, используйте уведомление. Принципы и шаблоны текстов уведомлений и тостов — в редполитике, раздел «Уведомления и тосты» (4.6).

---

## Анатомия

1. **ContentBefore** — иконка перед текстом (опционально, см. свойство ContentBefore).
2. **Toast text** — текстовый контент уведомления.
3. **Иконка закрытия** — крестик для ручного скрытия. В дизайн-макете отдельным элементом анатомии не выделена.

> Toast не содержит кнопку действия. Это соответствует редполитике ДС: «тост» = только информирование, без интерактивных действий.

## Настройки (Props)

> Здесь — визуальное поведение из дизайн-макета. Полный список пропсов с типами — в dev-документации.

### Тема контейнера (Style)

Свойство **Style** в дизайне задаёт цветовую тему (светлая/тёмная подложка).

| Значение в дизайне | Назначение |
|---|---|
| **Default** | Тост на стандартной (светлой) теме. |
| **OnDark** | Тост на тёмной подложке. |
| **Inverse** | Инверсная тема (тёмный тост). |
| **OnLight** | Тост на светлой подложке. |

### Вид

Свойство **View** в дизайне задаёт цветовую семантику и цвет иконки.

| Вид | Назначение |
|---|---|
| **Default** | Дефолтный (нейтральный) тост. |
| **Positive** | Позитивный сценарий (успех). |
| **Negative** | Негативный сценарий (ошибка). |
| **Info** | Информационный тост. |

### Скруглённость (Shape)

| Значение в дизайне | Результат |
|---|---|
| **Cornered** | Квадратный тост (скругление по Corner Radius). |
| **Rounded** | Круглый тост (полное скругление). |

### Иконка перед текстом (ContentBefore)

| Значение в дизайне | Результат |
|---|---|
| **True** | Включено отображение иконки перед текстом. |
| **False** | Выключено отображение иконки перед текстом. |

Иконка появляется слева от текста и окрашивается по виду тоста (Positive / Negative).

## Механика и взаимодействия

Тост всплывает поверх контента на короткое время, не блокирует взаимодействие и не требует обязательного закрытия.

**Расположение.** Тост появляется с отступом 12px от шапки (Header) платформы.

**Несколько тостов.** Одновременно показываются 1–2 тоста друг под другом с отступом 8px между ними. При появлении третьего и последующих самые ранние тосты пропадают, освобождая место новым. Максимум на экране — 1–3 тоста (точное число определяет продукт).

Конкретные параметры (авто-исчезновение по таймеру, позиция сверху/снизу, ручное закрытие крестиком) задаются в коде — примеры в Storybook: {{Storybook URL Toast}}.

## Маппинг: дизайн → код

|---|---|---|---|

## FAQ

### Для дизайнеров

**Q: Может ли тост содержать кнопку действия?**
A: Нет. Тост — это краткое информирование о статусе действия, он не несёт в себе дополнительных действий. Если нужна кнопка действия, это уже не тост, а уведомление с действием. Подробнее — в Pixso-документации компонента, блок «Анатомия»: {{Pixso URL Toast Doc Block 1}}.

**Q: Как сделать тост со скруглёнными краями?**
A: Через свойство Shape: Rounded — круглый тост (полное скругление), Cornered — квадратный (скругление по Corner Radius). Подробнее — в Pixso-документации компонента, блок «Скруглённость (Shape)»: {{Pixso URL Toast Doc Block 1}}.

**Q: Как добавить иконку перед текстом?**
A: Включить свойство ContentBefore → True. Иконка появится слева от текста и будет окрашиваться по виду тоста. Подробнее — в Pixso-документации компонента, блок «Иконка перед текстом (ContentBefore)»: {{Pixso URL Toast Doc Block 1}}.

**Q: Как сделать тост зелёным/красным?**
A: Через свойство View: Positive — для успеха (зелёный), Negative — для ошибки (красный). Цвет задаёт семантику сценария и окрашивает иконку. Подробнее — в Pixso-документации компонента, блок «Вид (view)»: {{Pixso URL Toast Doc Block 1}}.

**Q: Как поменять тему (светлый/тёмный)?**
A: Через свойство Style: Default / OnLight — для светлой подложки, OnDark / Inverse — для тёмной. Подробнее — в Pixso-документации компонента, блок «Тема контейнера (Style)»: {{Pixso URL Toast Doc Block 1}}.

**Q: Чем тост отличается от Note?**
A: Toast — всплывающее временное уведомление поверх контента; Note — инлайн-плашка, встроенная в поток страницы.

**Q: Когда показывать тост, а когда уведомление?**
A: Тост — для коротких технических оповещений о статусе, не являющихся целевым действием («Сохранено», «Скопировано», «Синхронизировано»). Уведомление — для результата целевого действия пользователя и когда нужна кнопка действия. Подробнее — в редполитике, раздел «Уведомления и тосты» (4.6).

### Для разработчиков

**Q: Как задать вид (семантику) тоста?**
A: Через проп `view`: `default` / `positive` / `negative` / `info`. Цвет иконки наследуется от вида при `color="inherit"`. Примеры кода — в Storybook: {{Storybook URL Toast}}.

**Q: Как сделать тост со скруглёнными краями?**
A: Через проп `pilled` (boolean): `true` — круглый (Rounded), `false` — квадратный (Cornered). Примеры кода — в Storybook: {{Storybook URL Toast}}.

**Q: Как добавить иконку перед текстом?**
A: Передать иконку в слот `contentLeft`. Чтобы иконка окрашивалась по виду, задайте у неё `color="inherit"`. Примеры кода — в Storybook: {{Storybook URL Toast}}.

**Q: Как задать размер?**
A: Через проп `size`. В дизайне текст фиксирован как TextXS N. Примеры кода — в Storybook: {{Storybook URL Toast}}.

**Q: Где появляется тост на экране?**
A: Через проп `position`: `top` или `bottom`. Примеры кода — в Storybook: {{Storybook URL Toast}}.

**Q: Как настроить, сколько времени тост виден?**
A: Через `timeout` (мс). Если значение не передать, тост будет виден, пока пользователь его не закроет. Примеры кода — в Storybook: {{Storybook URL Toast}}.

**Q: Как показать крестик закрытия?**
A: Через проп `hasClose` (boolean). Примеры кода — в Storybook: {{Storybook URL Toast}}.

**Q: Как поменять тему (светлый/тёмный)?**
A: Тема задаётся не на самом `Toast`, а на оборачивающем компоненте `ViewContainer` (проп `view`: `onLight` / `onDark`). Примеры кода — в Storybook: {{Storybook URL Toast}}.
