# Обновление библиотеки

Гайд о том, как безопасно обновить свои макеты на новую версию библиотеки дизайн-системы: что нового в обновлении, чем помогает инструмент Deep Search, как подготовить файл, в каком порядке обновлять компоненты и стили и как проверить результат.

---

## Про обновление

Обновление библиотеки SDDS FinAl — самое масштабное обновление дизайн-системы: новый визуальный стиль и улучшения качества жизни в работе с компонентами.

### Маркировка компонентов

Актуальные компоненты теперь начинаются в названии со значка 💎 вместо прежнего 🌕. По этому значку проще быстро находить в макетах устаревшие компоненты и оперативно их исправлять.

### Описание компонента (Description)

У каждого компонента появилось описание (Description). Оно решает ситуацию, когда имя компонента в правой панели сбрасывается на служебный набор параметров и полное название компонента не видно.

В описании компонента есть:

- Актуальное название компонента (например, 💎 IconButton 40 S).
- Ссылка на нужный компонент и нужный размер в Storybook.
- Вспомогательный текст для дизайнеров о том, как правильно настраивать компонент, — например, когда есть баг, который пока нельзя исправить.

### Как посмотреть описание

**Разработчику.** Работает и в режиме Dev.mode, и в режиме View. Выделите нужный компонент и откройте в правой панели Pixso вкладку Handoff (обычно она уже открыта) — там показываются описание и ссылка (Link) на компонент. Длинные описания можно развернуть или свернуть.

**Дизайнеру.** При клике на компонент в правой панели Pixso на вкладке Design (там, где идёт работа) отображается название компонента, ниже — его описание, а рядом при наведении на описание появляется кнопка View details.

## Deep Search

Deep Search — инструмент Pixso, который помогает при обновлении: с его помощью легко находить «сломанные» компоненты и ускорять работу.

### Как открыть

Например, в файл попал чужой компонент из мастер-библиотеки, и его нужно быстро заменить на свой:

- Сначала находим нужный компонент через Component — Used (сверху слева).
- Находим этот компонент на макетах.
- Выделяем компонент, щёлкаем правой кнопкой мыши на канвасе и выбираем Deep Search. Другой путь — бургер-меню сверху справа → Edit → в самом низу список опций Select…

### Самые полезные опции

- **Select the same instance** — выделяет такие же инстансы (например, все кнопки IconButton 40 S).
- **Select a instance with the same variant attribute** — выделяет такие же инстансы, но только с теми же настройками варианта, что выставлены у выбранного компонента (например, все IconButton 40 S с настройкой View=accent).
- **Select the same text style** — выделяет текст с тем же стилем, что у выбранного. Помогает найти текст, у которого не привязан токен.

Остальные опции Select тоже полезны — их стоит попробовать самостоятельно.

## Подготовка файла

Перед обновлением файл нужно подготовить — чтобы обновиться максимально безопасно и не потерять важные данные.

### Создаём дубликат файла

Сделайте дубликат своего макета — пусть он лежит рядом как ориентир.

- Зайдите в место хранения файла в Pixso.
- Нажмите «…» и выберите Duplicate.
- Создастся файл с именем вида «[Название файла] Copy».
- Переименуйте его в «Дубликат. НЕ ТРОГАТЬ».
- По желанию поменяйте фон всего файла, чтобы копию было легко отличать от основного файла.

### Сохраняем версию файла

Сохраните версию файла и в дубликате, и в основном файле, в котором будете обновляться.

- Откройте файл.
- Сверху у названия файла нажмите на шеврон и выберите View version history.
- Справа в появившемся окне нажмите + и добавьте новую версию.
- Затем нажмите Back to edit справа у названия.

### Зачем это нужно

- Всегда под рукой необновлённый дубликат, с которым можно сверяться.
- С дубликата удобно скопировать правильный текст внутри компонента, если он сбросился.
- Если что-то сломается, есть сохранённая версия, к которой можно вернуться в критической ситуации.
- Если срочно нужно показать макеты PO, можно использовать дубликат, пока обновляется основная версия.

## Как обновляться?

Обновление идёт по порядку: сначала подготовка, затем компоненты, затем стили.

### Шаг 1. Читаем «Подготовку файла»

К этому шагу у вас уже должны быть дубликат и сохранённая версия файла.

Если файлов несколько (например, есть отдельный файл с локальными компонентами), сначала обновляем файл с локальными компонентами, а затем — другие связанные файлы. Компоненты из одной библиотеки старайтесь обновлять вместе (например, несколько компонентов из Data Entry).

Порядок обновления библиотек — в таком порядке больше шансов, что всё обновится корректно:

1. Data Entry
2. Data Display
3. Data Entry inputs
4. Data Entry dropdown
5. Navigation
6. Data Entry upload
7. Overlay
8. Tree
9. Остальное

### Шаг 2. Обновляем компоненты

- Нажмите вкладку Component.
- Справа кликните на иконку Library.
- Перейдите во вкладку Updates.

Сценарий обновления:

- Выделяйте до 8–10 компонентов и обновляйте.
- Дождитесь, пока обновится.
- Повторяйте, пока не обновите все компоненты.

После каждого апдейта пройдитесь по макетам и посмотрите на обновлённые компоненты — всё ли с ними хорошо.

**Замена deprecated-компонентов.** Чтобы заменить сразу много одинаковых устаревших компонентов, помогает приём на основе Deep Search:

- Сначала настройте отдельный компонент под свои данные (вид, контент и т. д.) — например, Badge 28 L.
- Скопируйте этот компонент.
- Когда выделятся все места, где используется такой компонент, замените его на актуальный с нужными настройками.

Приём работает, когда контент одинаковый.

### Шаг 3. Обновляем стили

После обновления всех компонентов обновите стили — тогда макеты перейдут от серого к голубому.

- Если всё сделано правильно, останутся только стили.
- Можно обновить все стили сразу: выделите все стили и нажмите Update.
- Результат можно сравнить с дубликатом — цвета должны измениться (если вы не перекрашивали компоненты вручную).

## Проверка

Финальный шаг — проверить, что в макетах не осталось устаревших компонентов.

### Проверяем макеты на актуальные компоненты

- Откройте Component — Used и переключите на режим «список».
- Проверьте, что нет компонентов с пометкой ❌ (deprecated).
- Если такой компонент найден, замените его на новый актуальный: 🔷 — для организмов, 💎 — для атомов.

После этих шагов обновление завершено. Если что-то сбросилось или пока работает не идеально — часть доработок ещё в процессе.

Подробнее, с иллюстрациями — в документации гайда, блок «Проверка»: {{Pixso URL LibraryUpdate Doc Block 5}}

## FAQ

### Для дизайнеров

**Q: Что нового в этом обновлении дизайн-системы?**
A: Новый визуальный стиль, обновлённая маркировка компонентов (💎 вместо 🌕) и описание (Description) у каждого компонента. Подробнее — блок «Про обновление»: {{Pixso URL LibraryUpdate Doc Block 1}}

**Q: Что означает значок 💎 в начале названия компонента?**
A: Это актуальный компонент. Прежние компоненты начинались с 🌕 — по значку удобно быстро находить в макетах устаревшие компоненты. Подробнее — блок «Про обновление»: {{Pixso URL LibraryUpdate Doc Block 1}}

**Q: Что такое Description у компонента и что в нём есть?**
A: Это описание компонента: актуальное название, ссылка на нужный компонент и размер в Storybook и вспомогательный текст о том, как правильно его настраивать. Подробнее — блок «Про обновление»: {{Pixso URL LibraryUpdate Doc Block 1}}

**Q: Как посмотреть описание компонента?**
A: Дизайнеру — при клике на компонент на вкладке Design в правой панели (название, описание и кнопка View details при наведении). Разработчику — на вкладке Handoff (описание и ссылка на компонент). Подробнее — блок «Про обновление»: {{Pixso URL LibraryUpdate Doc Block 1}}

**Q: Как быстро найти на макетах все копии одного компонента?**
A: Через Deep Search — опция Select the same instance выделяет все такие же инстансы. Подробнее — блок «Deep Search»: {{Pixso URL LibraryUpdate Doc Block 2}}

**Q: Как найти текст, у которого не привязан токен?**
A: В Deep Search выбрать опцию Select the same text style — она выделит весь текст с тем же стилем. Подробнее — блок «Deep Search»: {{Pixso URL LibraryUpdate Doc Block 2}}

**Q: Как подготовить файл перед обновлением?**
A: Сделать дубликат файла («Дубликат. НЕ ТРОГАТЬ») и сохранить версию файла и в дубликате, и в основном файле. Подробнее — блок «Подготовка файла»: {{Pixso URL LibraryUpdate Doc Block 3}}

**Q: Зачем нужны дубликат и сохранённая версия?**
A: Чтобы было с чем сверяться, откуда скопировать правильный текст, если он сбросился, к чему вернуться при поломке и что показать PO, пока обновляется основная версия. Подробнее — блок «Подготовка файла»: {{Pixso URL LibraryUpdate Doc Block 3}}

**Q: В каком порядке обновлять компоненты из библиотек?**
A: Data Entry → Data Display → Data Entry inputs → Data Entry dropdown → Navigation → Data Entry upload → Overlay → Tree → остальное. В этом порядке больше шансов, что всё обновится корректно. Подробнее — блок «Как обновляться?»: {{Pixso URL LibraryUpdate Doc Block 4}}

**Q: Как обновлять компоненты и по сколько за раз?**
A: На вкладке Component → иконка Library → вкладка Updates выделять по 8–10 компонентов, обновлять, дожидаться и повторять, пока не обновите все. После каждого апдейта проверять макеты. Подробнее — блок «Как обновляться?»: {{Pixso URL LibraryUpdate Doc Block 4}}

**Q: Как заменить сразу много одинаковых устаревших компонентов?**
A: Настроить один компонент под свои данные, скопировать его и заменить им все найденные места использования; приём работает, когда контент одинаковый. Подробнее — блок «Как обновляться?»: {{Pixso URL LibraryUpdate Doc Block 4}}

**Q: Когда обновлять стили?**
A: После того как обновлены все компоненты: выделить все стили и нажать Update — макеты перейдут от серого к голубому. Подробнее — блок «Как обновляться?»: {{Pixso URL LibraryUpdate Doc Block 4}}

**Q: Как проверить, что не осталось устаревших компонентов?**
A: Открыть Component — Used в режиме «список» и убедиться, что нет компонентов с пометкой ❌ (deprecated). Подробнее — блок «Проверка»: {{Pixso URL LibraryUpdate Doc Block 5}}

**Q: Чем заменить найденный deprecated-компонент?**
A: Новым актуальным компонентом: 🔷 — для организмов, 💎 — для атомов. Подробнее — блок «Проверка»: {{Pixso URL LibraryUpdate Doc Block 5}}
