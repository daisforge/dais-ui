# Modal

Модальное окно — всплывающее окно поверх страницы, которое появляется в ответ на действие пользователя и блокирует доступ к основному содержимому, пока открыто. Помогает сфокусировать внимание на конкретной задаче, не теряя общий контекст страницы.

Визуал: {{Pixso URL ModalDF Doc Block 1}}

---

## Когда использовать

Используйте модальное окно для второстепенного содержимого, которое нужно лишь в некоторых случаях, или чтобы сосредоточить внимание пользователя на выполняемом действии. Как правило, это настройки, создание новых документов, заполнение небольших форм, пошаговый мастер, а также удаление данных и подтверждение сохранения изменений.

Типичные кейсы:

- Выбор сущности.
- Подтверждение действия.
- Создание новой сущности.

## Когда не используем

Не используйте модальное окно для блоков с фильтрацией и просмотра большого объёма данных — там важно сохранить контекст страницы. Для таких сценариев подходит [Drawer]({{Storybook URL DrawerDF}}) — выезжающая боковая панель, которая сохраняет контекст. И наоборот: для подтверждений, коротких сообщений и создания новых сущностей выбирайте модальное окно, а не Drawer.

Сравнение сценариев Modal и Drawer: {{Pixso URL ModalDF DocGuide Block 2}}

## Анатомия

1. **Шапка** — заголовок, подзаголовок и бейдж, правый блок действий (кнопки-ссылки), кнопка «назад» и меню «троеточие», а также сервисные кнопки: раскрытие на весь экран и закрытие.
2. **Левый сайдбар** — дополнительный боковой блок слева (опционально). Может содержать кастомный контент.
3. **Контент-зона** — основная область окна. По умолчанию это кастомный блок, который заменяется на любой компонент через Instance swap.
4. **Подвал** — кнопки основных действий, разделённые на левый и правый блоки.
5. **Разделитель** — линия между блоками окна.

Сервисные кнопки (раскрытие на весь экран и закрытие) доступны даже без шапки.

Действия в окне:

- **Главная кнопка** (синяя) — целевое действие: сохраняет проделанную работу или подтверждает ранее вызванную команду.
- **Вторичная кнопка** — отменяет действие или несёт дополнительный функционал.
- **Кнопки в правом верхнем углу** — действия с самим окном и его содержимым.
- **Кастомный блок** — заменяется на любой компонент через Instance swap.
- **Сайдбар** — боковой блок слева, может содержать кастомный блок.

## Заголовок и тексты

Заголовок задаёт смысл окна. Это **название процесса или объекта**, а не призыв к действию.

- Если окно предназначено для одной конкретной задачи, эта задача отражается в заголовке. Заголовок краткий — 1–3 слова.
- Если окно носит информационный характер, заголовок ёмко передаёт суть сообщения.
- В окнах с подтверждением заголовком может быть вопрос.

| ❌ Не так | ✅ Так | Тип окна |
|---|---|---|
| Создать отчёт | Создание отчёта | Окно одной задачи |
| Заполните информацию об инициативе | Информация об инициативе | Окно одной задачи |
| — | Обратитесь к технической поддержке | Информационное окно |
| — | Удалить данные? | Окно подтверждения |

Общие правила текстов и заголовков — в редполитике (разделы «Правописание» и «Кнопки»).

## Confirmation Modal — окно подтверждения

Окно подтверждения запрашивает у пользователя подтверждение перед выполнением потенциально необратимого действия. Построено на базе модального окна; фон затемняется той же подложкой, что и у модального окна.

Визуал: {{Pixso URL ModalConfirmationModal}} · Варианты: {{Pixso URL VariantsConfirmationModal}}

### Зачем нужно

- Предупреждает о необратимости действия — например, о безвозвратной потере данных.
- Снижает количество ошибок: пользователь может случайно нажать кнопку или клавишу закрытия — тогда система показывает окно подтверждения и помогает затормозить процесс.
- Повышает осознанность выбора пользователя.

Зачем нужно: {{Pixso URL ModalConfirmationModal Doc Block 1}}

### Примеры использования

- Подтверждение удаления данных.
- Выход без сохранения.
- Изменение настроек с необратимыми последствиями.
- Другие критически важные действия, которые сложно или невозможно отменить.

Примеры использования: {{Pixso URL ModalConfirmationModal Doc Block 2}}

### Структура и поведение

Окно появляется поверх текущего интерфейса и блокирует взаимодействие с ним; фон затемняется той же подложкой, что и у модального окна. Все окна подтверждения выглядят единообразно. Окно можно закрыть крестиком — пользователь остаётся на том же шаге пользовательского сценария. После закрытия окна оповестите пользователя уведомлением (например, «Изменения сохранены», «Данные удалены»).

Структура и поведение: {{Pixso URL ModalConfirmationModal Doc Block 3}}

### Рекомендации по наполнению

- **Заголовок** — кратко и ёмко передаёт смысл действия, которое собирается выполнить пользователь. Может быть вопросом или утверждением о совершаемом действии; формулировка максимально ёмкая, но описывает суть процесса.
- **Основной текст** — краткое описание того, что произойдёт, если пользователь выполнит действие. Для названий кнопок используйте одинаковые глагольные формы.
- **Кнопки** — обычно пара: главная (status) и вторичная (secondary). Цвет главной кнопки зависит от типа окна (Positive, Negative, Warning, Info). Не злоупотребляйте кнопками красного цвета — они только для привлечения внимания к критически важным решениям.

Конкретные формулировки заголовка, основного текста и кнопок — по редполитике (разделы «Кнопки» и «Tone of voice»).

Рекомендации по наполнению: {{Pixso URL ModalConfirmationModal Doc Block 4}}

## Механика и взаимодействия

- **Затемнение фона.** Окно накладывается поверх затемнённого экрана — используются токены цвета из группы Overlay (`darkOverlayBlur`). Окно подтверждения использует ту же подложку, что и модальное окно.
- **Блокировка страницы.** Пока окно открыто, скролл и фокус основной страницы блокируются.
- **Полноэкранный режим.** Раскрытие на весь экран сервисной кнопкой; состояние может сохраняться между открытиями.
- **Перетаскивание и изменение размера.** Окно можно перемещать по экрану и растягивать.
- **Захват фокуса.** При включённом захвате навигация с клавиатуры (Tab / Shift+Tab) удерживается внутри окна. Если поверх открывается ещё одно окно, фокус захватывает верхнее. После закрытия фокус освобождается.
- **Анимация.** Появление и исчезновение окна и подложки можно анимировать.
- **Закрытие.** Крестик или клавиша Esc.

---

## Краевые сценарии

- **Вложенные окна.** Поверх открытого окна можно открыть другое; фокус захватывает верхнее окно, после его закрытия — возвращается к нижнему.
- **Сервисные кнопки без шапки.** Кнопки «на весь экран» и «закрыть» доступны, даже если шапка не используется.
- **Сохранение полноэкранного режима.** Полноэкранный режим может сохраняться между открытиями окна (настраивается).

## Маппинг: дизайн → код

В коде стилизованное модальное окно — компонент `ModalDF` (обёртка над базовым модальным окном дизайн-системы). Для работы окон требуется обёртка `PopupProvider`. Базовые поведения (открытие, расположение, перетаскивание, изменение размера, захват фокуса, анимация) наследуются от базового модального окна.

| Свойство в дизайне | Проп / компонент в коде | Значения | Примечание |
|---|---|---|---|
| Открытие / закрытие | `opened`, `onClose` | boolean / callback | Базовые пропсы модального окна. |
| Расположение | `placement` | center / right | В дизайне Modal — по центру; боковые сценарии — территория Drawer. |
| Смещение | `offset` | [x, y] | Сдвиг окна. |
| Затемнение фона (Overlay) | подложка окна + `zIndexOverlay`; класс `.modal-overlay` (`modalClasses.overlay`) | z-index / CSS | Токены `darkOverlayBlur` — на стороне дизайна. |
| Шапка | `ModalDF.Header` | `title`, `subTitle`, `badge`, `rightBlock`, `showBackButton`, `onBackClick` | Заголовок, подзаголовок, бейдж, правый блок, кнопка «назад». |
| Подвал | `ModalDF.Footer` | `leftBlock`, `rightBlock` | Левый и правый блоки кнопок. |
| Левый сайдбар + основная колонка | `ModalDF.Left` + `ModalDF.Main` | — | Двухколоночная раскладка. |
| Контент-зона / кастомный блок | `ModalDF.Content`, `contentContainerProps`; `children` | — | Контент через Instance swap; ширину задают через `contentContainerProps`. |
| Разделитель | `ModalDF.Divider` | — | Линия между блоками. |
| Сервисные кнопки (на весь экран / закрыть) | `ModalDF.ServiceButtons` | — | Доступны даже без шапки. |
| Кнопка-меню «троеточие» | `ModalDF.DotsIconButton` | `dropdownProps`, `iconSize` | Иконка «троеточие» с выпадающим меню. |
| Кнопка «назад» | `ModalDF.BackIconButton` / `showBackButton` | — | — |
| Полноэкранный режим | `fullScreen` | `{ defaultEnabled, saveStateAfterClosing, onFullScreen, onExitFullScreen }` \| boolean | Сохранение состояния — `saveStateAfterClosing`. |
| Перетаскивание | `draggable` | boolean | — |
| Изменение размера | `resizable` | объект (directions / min / max / defaultSize / icons) | — |
| Захват фокуса | `isFocusTrapped` | boolean | — |
| Анимация | `withAnimation` | `modalClasses`, `popupClasses` | — |
| Стилизованная обёртка (отступы + крестик) | `hasBody` | boolean | В `ModalDF` включена по умолчанию; в базовом окне — отдельный проп. |
| Подключение | `PopupProvider` | — | Обязательная обёртка. |

## FAQ

### Для дизайнеров

**Q: Когда использовать модальное окно, а когда Drawer?**
A: Модальное окно — для второстепенного содержимого и фокуса на действии: настройки, создание документов, небольшие формы, удаление и подтверждение. Drawer — когда важно сохранить контекст страницы и показать большой объём данных (просмотр сущности, фильтры). Подробнее — в Pixso-документации компонента, блок «Когда использовать»: {{Pixso URL ModalDF}}.

**Q: Какой минимальный и максимальный размер у модального окна?**
A: Минимальная ширина — от 400px (кратно 4). Максимальный размер — на весь экран с отступами по 16px по сторонам. Левый сайдбар — от 280px до 360px. Подробнее — в Pixso-документации компонента, блок «Размеры и отступы»: {{Pixso URL ModalDF}}.

**Q: Что такое окно подтверждения и когда его применять?**
A: Это модальное окно, которое запрашивает подтверждение перед потенциально необратимым действием: удаление данных, выход без сохранения, критичные изменения настроек. Подробнее — в Pixso-документации компонента, блок «Confirmation Modal»: {{Pixso URL ModalConfirmationModal}}.

**Q: Каким должен быть заголовок модального окна?**
A: Это название процесса или объекта, а не призыв к действию: «Создание отчёта», а не «Создать отчёт». Для информационного окна заголовок ёмко передаёт суть, для подтверждения — может быть вопросом. Подробнее — в Pixso-документации компонента, блок «Заголовок»: {{Pixso URL ModalDF}}.

**Q: Можно ли раскрыть окно на весь экран?**
A: Да, сервисной кнопкой в шапке. Состояние полноэкранного режима может сохраняться между открытиями. Подробнее — в Pixso-документации компонента, блок «Размеры и отступы»: {{Pixso URL ModalDF}}.

**Q: Что показать пользователю после закрытия окна подтверждения?**
A: Оповестите его уведомлением о результате действия — например, «Изменения сохранены» или «Данные удалены». Подробнее — в Pixso-документации компонента, блок «Структура и поведение»: {{Pixso URL ModalConfirmationModal}}.

**Q: Сколько кнопок в окне подтверждения и какого они цвета?**
A: Обычно пара: главная и вторичная. Цвет главной кнопки зависит от типа окна (Positive, Negative, Warning, Info). Красный цвет — только для критически важных решений. Подробнее — в Pixso-документации компонента, блок «Рекомендации по наполнению»: {{Pixso URL ModalConfirmationModal}}.

### Для разработчиков

**Q: Какой компонент использовать для стилизованного модального окна?**
A: `ModalDF` — стилизованная обёртка дизайн-системы. Для работы окон оберните приложение в `PopupProvider`. Примеры кода — в Storybook: {{Storybook URL ModalDF}}.

**Q: Как собрать шапку, подвал и двухколоночную раскладку?**
A: Compound-компонентами: `ModalDF.Header` (заголовок, подзаголовок, бейдж, правый блок, кнопка «назад»), `ModalDF.Footer` (`leftBlock`, `rightBlock`), `ModalDF.Left` + `ModalDF.Main` для двух колонок, `ModalDF.Content` для контейнера контента. Примеры кода — в Storybook: {{Storybook URL ModalDF}}.

**Q: Как включить полноэкранный режим с сохранением состояния?**
A: Пропом `fullScreen` — объектом `{ defaultEnabled, saveStateAfterClosing, onFullScreen, onExitFullScreen }` или булевым значением. За сохранение между открытиями отвечает `saveStateAfterClosing`. Примеры кода — в Storybook: {{Storybook URL ModalDF}}.

**Q: Как сделать окно перетаскиваемым или растягиваемым?**
A: Пропом `draggable` (перетаскивание) и `resizable` (изменение размера — объект с направлениями и ограничениями по минимуму/максимуму). Примеры кода — в Storybook: {{Storybook URL ModalDF}}.

**Q: Как удержать фокус внутри окна?**
A: Пропом `isFocusTrapped` — при `true` навигация Tab / Shift+Tab остаётся внутри окна. Примеры кода — в Storybook: {{Storybook URL ModalDF}}.

**Q: Как реализовать окно подтверждения в коде?**
A: Компонентом `ModalDFConfirmation` (на базе `ModalDF`). Наполнение — через `content` (`header`, `body`, `mainButton`, `secondaryButton`, `footer`), цветовой акцент по типу — через `view`, иконка вверху — через `icon`. Примеры кода — в Storybook: {{Storybook URL ModalDF}}.

**Q: Как задать ширину окна и z-index подложки?**
A: Ширину рекомендуется задавать через `contentContainerProps`, z-index подложки — через `zIndexOverlay`. Примеры кода — в Storybook: {{Storybook URL ModalDF}}.
