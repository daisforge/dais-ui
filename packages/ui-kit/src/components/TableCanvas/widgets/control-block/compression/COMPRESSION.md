# Компрессия ControlBlock — спецификация

Как контрл-блок таблицы умещает своё содержимое в доступную ширину. Документ
описывает раскладку, модель ширины, порядок сжатия, замеры, кэш и краевые
сценарии. Это «карта» к коду в этой папке; точные детали — в комментариях
файлов (`steps.ts`, `width-model.ts`, `measure.ts`, `index.ts`).

---

## 1. Зачем

Контрл-блок — одна строка фиксированной высоты с кучей элементов (кнопки,
поиск, фичи-иконки, заголовок/коллапс). Когда таблица узкая, всё это не
влезает. Компрессия по шагам уменьшает контент, пока он не поместится в
`availableWidth`, и только потом отдаёт остаток в горизонтальный скролл.

Алгоритм **детерминированный**: для одной и той же ширины всегда получается
одно и то же состояние, поэтому осцилляций (сжали → расширили → сжали) не
бывает по построению.

---

## 2. Раскладка (схема)

Слева направо контрл-блок состоит из зон. В скобках — поле спейсинга, которое
добавляет промежуток/паддинг.

```
┌─ ControlBlock ────────────────────────────────────────────────────────────┐
│ (containerPadding)                                          (containerPadding)│
│                                                                              │
│  ЛЕВАЯ ЧАСТЬ                  СЕРЕДИНА            ПРАВАЯ ЧАСТЬ                │
│  ┌───────────────────────┐   ┌─────────┐   ┌───────────────────────────────┐│
│  │ [collapse] [inlineTit] │   │ search  │   │ buttons │ icons        «…»     ││
│  │ editSlot  edit-buttons │   │ (minW)  │   │         │ rowSize fullScreen  ││
│  │ leftSideInner-блок     │   │         │   │ keyText │                     ││
│  └───────────────────────┘   └─────────┘   │ grouping│ customFeatures      ││
│   (leftPartGap, leftPartPaddingRight)        └───────────────────────────────┘│
│                                              (rightButtonsGap/Padding, divider)│
└────────────────────────────────────────────────────────────────────────────┘
```

- **Левая часть** (`LefSideStyled`): кнопка коллапса, inline-заголовок,
  `editModeLeftSlot`, кнопки редактирования (Отменить/Сохранить или
  Редактировать), блок `leftSideInner` (дропдаун «Действия» при 2+ кнопках,
  иначе одна кнопка). Не сжимается покомпонентно — это «тяжёлая» зона.
- **Середина**: поиск. Его ширина = `searchingFeature.minWidth` (обычно 250,
  при сжатии может уйти к 210). Поиск **никогда не уезжает вниз** — всегда
  inline.
- **Правая часть**: зона кнопок (`rightSideInner` + встроенные фичи — ключ-текст,
  группировка) и зона иконок (`customFeatures`, плюс связка `fullScreen`+`rowSize`
  справа). Между зонами — вертикальный дивайдер. Триггер overflow «…» живёт в
  зоне иконок.

Порядок правой части в DOM — `row-reverse`: самые правые — `fullScreen`, левее
`rowSize`, затем «…», затем остальные фичи.

## 3. Модель ширины (`width-model.ts` → `calculateWidth`)

Чистая функция: на вход состояние видимости + замеры ширин + спейсинги, на
выход — суммарная ширина контента. Складываем по слагаемым:

| Слагаемое            | Когда                                   | Откуда ширина                       |
| -------------------- | --------------------------------------- | ----------------------------------- |
| containerPadding × 2 | всегда                                  | спейсинг                            |
| inlineTitle          | inline-заголовок виден                  | DOM-замер                           |
| collapseBlock        | активна кнопка коллапса                 | DOM-замер                           |
| leftGaps + padding   | есть коллапс ИЛИ внутренние левые элем. | спейсинг                            |
| editModeLeftSlot     | editMode активен                        | DOM-замер                           |
| edit-кнопки          | фича редактирования активна             | с лейблом / icon-only (DOM-замер)   |
| leftSideInnerBlock   | есть leftSideInner                      | DOM-замер (целиком, не сжимается)   |
| search               | поиск активен                           | `minWidth` (250 ↔ 210)              |
| правые кнопки        | каждая видимая (не в дропдауне)         | с лейблом / icon-only (DOM-замер)   |
| groupingCounter      | у группировки есть счётчик колонок      | константа `GROUPING_COUNTER_WIDTH`  |
| customFeatures       | каждая видимая иконка                   | DOM-замер (дивайдер вшит в ширину)  |
| divider              | есть и кнопки, и иконки                 | 1px                                 |
| right paddings/gaps  | есть видимые кнопки                     | спейсинг                            |
| overflowTrigger «…»  | триггер виден                           | DOM-замер                           |

Все замеры округляются **вверх** (`Math.ceil`): модель не должна
недооценивать доли пикселя, иначе остаётся скролл в 1–3px.

## 4. Алгоритм компрессии (`index.ts` → `compress`, `steps.ts`)

```
compress(availableWidth):
  1. нет замеров лейблов → skip (иначе кнопки посчитаются как 0 → ложно «влезает»)
  2. есть в кэше диапазон под availableWidth → отдать кэш, стоп
  3. взять несжатое состояние (клон originalState)
  4. посчитать ширину. Влезает → стоп («0: initial fits»)
  5. иначе прогнать КОНВЕЙЕР шагов; после каждого шага мерить — влезло → стоп
  6. если шаги кончились — по одному уводить элементы в overflow-дропдаун
     (с конца массива, справа налево); после каждого мерить — влезло → стоп
  7. всё сжали, не влезло → максимально сжатое состояние, остаток в скролл
```

### Конвейер шагов (`getCompressionPipeline`)

Порядок шагов = спецификация. Зависит от контекста:

| Контекст                | Порядок шагов                                                        |
| ----------------------- | ------------------------------------------------------------------- |
| обычный                 | 1) лейблы правых кнопок → icon-only · 2) лейбл «Редактировать»       |
| есть счётчик группировки| 1) поиск 250→210 · 2) лейблы правых кнопок · 3) лейбл «Редактировать»|
| режим редактирования    | 1) лейблы Отменить/Сохранить · 2) поиск 250→210 (если editModeLeftSlot) · 3) лейблы правых кнопок |

Шаг «применяется», только если ему есть что сжимать (`step.applies`).

### Overflow-дропдаун

Когда шаги исчерпаны, элементы по одному уходят в дропдаун «…». Список и
порядок строит `buildOverflowItems`:

- сначала **кастомные фичи** (только с `canBeCompressed = true`), затем
- **кнопки** правой зоны (встроенные фичи раньше конфиговых — они в конце массива).

Коллапс идёт **с конца** (справа налево по конфигу). Первый спрятанный элемент
включает триггер «…». Фича без `details` при нехватке места просто скрывается;
с `details` — показывается в дропдауне по своему типу (`button`/`switch`/
`select`/`custom`). Связка `fullScreen`+`rowSize` в дропдаун **не уходит**.

## 5. Замеры ширин (`measure.ts`)

Модели нужны реальные ширины из DOM (лейблы разной длины — константами не
обойтись). Правила:

- лейбл кнопки меряем только когда он **реально виден**; icon-only ширину —
  когда лейбл скрыт (текст убирается из DOM, а не через CSS → замер стабилен);
- блок «Действия» (`leftSideInner`) меряем целиком, он не сжимается;
- до первого замера работают **фоллбек-константы** (см. верх `measure.ts` и
  `width-model.ts`).

Замер запускается не на каждый рендер (это гоняло бы reflow), а по компактным
**сигнатурам**, которые меняются считанные разы: видимость лейблов
(`visSignature`), контент фич (`iconsSignature`), загрузка шрифтов
(`fontsTick`), длины массивов, `fullScreened`, `editModeEnabled`, `isCollapsed`.

---

## 6. Кэш диапазонов (`cache.ts`)

Кэш живёт по DOM-элементу таблицы и переживает ремаунт контрл-блока. Ключ кэша
— конфигурация, от которой зависит результат (`originalState`, замеры,
`editModeEnabled`, `hasEditModeLeftSlot`). Для одной конфигурации кэшируются
диапазоны ширины → состояние, так что повторные `compress` на близкой ширине
отдаются мгновенно. При смене конфигурации (новые замеры) кэш чистится.

---

## 7. Краевые сценарии

- **Режим редактирования.** Кнопки Отменить/Сохранить широкие — их лейблы
  прячем первыми, правую часть стараемся не трогать. Сжатие поиска до 210
  допускаем только если активен `editModeLeftSlot` (кастомный слот занял место).
- **Счётчик группировки.** Когда у кнопки «Группировать» появляется счётчик
  выбранных колонок, кнопка шире. Чтобы из-за этого не прятать лейблы, при
  сжатии **сначала жертвуем шириной поиска** (250→210). Ширину счётчика
  учитываем отдельным константным слагаемым (`GROUPING_COUNTER_WIDTH`), а не
  замером кнопки: иначе при скрытом лейбле счётчик «вмерзает» в замер и лейблы
  не возвращаются. См. `hasGroupingCounter`.
- **Коллапс таблицы.** Кнопка коллапса меняет текст (Свернуть ↔ Развернуть) —
  это разная ширина, поэтому `isCollapsed` в сигнатурах замера, модель
  пересчитывается.
- **Шрифты.** Первый замер на маунте ловит fallback-шрифт; после `document.fonts.ready`
  делается перезамер (`fontsTick`), иначе модель занижена и появляется скролл.

---

## 8. Детерминизм

`compress` всегда стартует с **несжатого** `originalState` и заново выводит
результат для текущей ширины. Это не «защёлка»: расширили окно → пересчитали с
нуля → лейблы вернулись. Поэтому осцилляций нет, а кэш безопасен.

---

## 9. Дебаг

Логи компрессии идут через shared-логгер (`createDebugLogger('CB')`), по
умолчанию **выключены**. Включить в консоли браузера:

```js
window.__CB_DEBUG__ = true;
```

Каждое событие — одна строка `[CB] {…JSON…}` (init, compress, skip), её удобно
скопировать целиком. В DevTools нужен уровень логов Verbose/Debug. См. `debug.ts`.
