# {{MCP_PACKAGE}}

MCP-сервер для `{{LIB_PACKAGE}}` — даёт кодовому агенту точные пропсы, типы, категории и примеры для всех компонентов библиотеки, а не только для задокументированных в Storybook.

## Установка

```bash
npm install {{LIB_PACKAGE}} {{MCP_PACKAGE}}
```

Конфиг MCP-клиента:

```json
{
  "mcpServers": {
    "{{URI_SCHEME}}": {
      "command": "node",
      "args": ["node_modules/{{MCP_PACKAGE}}/dist/server.js"]
    }
  }
}
```

Библиотека `{{LIB_PACKAGE}}` не обязательна: без неё сервер работает на вшитом индексе и предупреждает об этом в ответах (`libNotInstalled`). Если библиотека установлена и её версия несёт собственные данные, сервер берёт их — так пропсы всегда соответствуют именно вашей версии.

## Инструменты

- `list_components({ type?, category?, scope?, role?, limit?, offset? })` — каталог компонентов с фильтрами по типу (`wrapper`/`composition`/`standalone`/`form`), категории и области. По умолчанию отдаёт только самостоятельные компоненты (`role: "primary"`); слоты compound-компонентов и служебные примитивы скрыты, `role: "all"` снимает фильтр. Без `limit` список сам бюджетируется под лимит ответа — остаток добирается фильтрами или `limit`/`offset`.
- `search_components({ query })` — поиск по компонентам и фичам с учётом синонимов задачи на русском и английском. В результатах есть `chooseWhen`/`supersededBy` — по ним выбирают между конкурирующими компонентами.
- `get_component({ name })` — компактная карточка: описание, категория, `minimalUsage` (синтетический вызов из обязательных пропсов), заголовки доступных примеров, ссылки на родителя и связанные экспорты.
- `get_component_props({ name, part? })` — полные пропсы, собственные и унаследованные. Отсортированы: обязательные → с описанием → без описания → `deprecated` в конец, чтобы при обрезке по бюджету терялось наименее нужное.
- `get_component_examples({ name, title? })` — только настоящие примеры кода, до 4 суммарно.
- `list_features({ component })`, `get_feature({ component, feature })`, `get_feature_examples({ component, feature, title? })` — крупные возможности сложных компонентов (фильтрация, редактирование, выделение и т.п.) отдельно от плоского списка пропсов.
- `get_type({ name })` — определения типов, на которые ссылаются пропсы.

## Ресурсы

- `{{URI_SCHEME}}://catalog/categories` — категории каталога с количеством компонентов по типам.
- `{{URI_SCHEME}}://catalog/installation-guide` — установка пакета, подключение стилей и токенов, использование компонентов и иконок.

## Требования

Node.js >= 20.
