# A/B-замер пользы MCP (T10)

`validateIndex` проверяет, что индекс **не врёт**. Этот харнесс проверяет, что индекс **помогает**: одни и те же задачи на генерацию кода решаются агентом с MCP и без, в обстановке настоящего потребителя библиотеки.

## Одной командой

```bash
cd packages/mcp-server
npm run mcp:ab:consumer   # собрать стенд потребителя (первый раз)
npm run mcp:ab:drift      # измерить расхождение индекса и установленного пакета
npm run mcp:ab            # прогон + метрики
npm run mcp:ab:app        # собрать из ответов работающее приложение и проверить vite build
```

Отчёт — `.probe/ab/report.md`, сырые числа — `.probe/ab/results.json`, транскрипты — `.probe/ab/runs/`.

## Стенд: почему не исходники

Первая версия харнесса сравнивала MCP с грепом по `packages/ui-kit/src` — и мерила не то. **У потребителя библиотеки исходников нет**: есть установленный пакет, где у чистых реэкспортов `.d.ts` выглядит ровно как `export { Button } from '@salutejs/sdds-finai'`, то есть описаний пропсов нет вообще.

`ab/prepare-consumer.mjs` собирает песочницу **вне репозитория** (`~/.claude-ab-consumer`), чтобы агент не мог ни подняться в исходники, ни подхватить `CLAUDE.md` библиотеки:

- `@daisforge/ui` ставится **настоящим опубликованным пакетом из npm** (по умолчанию `1.12.2` — вплотную к локальным `1.12.1`, по которым собран индекс; `latest` дал бы лишний версионный дрейф);
- `@daisforge/ui-mcp` ставится из локального пака — в реестре его нет вовсе (404), поэтому индекс сервер резолвит запасной веткой `bundled` (`resolveIndex.ts`), и стенд заодно впервые прогоняет вживую потребительский путь резолва, а не workspace-ветку;
- скелет приложения взят из `packages/vite-project` (настоящее потребительское приложение монорепо), но **без его `src/pages`**: там 20 готовых страниц (`Button.tsx`, `Select.tsx`, `Table.tsx`…), пересекающихся с задачами замера — рука без MCP списала бы ответ оттуда;
- каркас `App` подхватывает любые страницы из `src/pages` через `import.meta.glob`, поэтому ответ агента сразу оказывается в работающем приложении, без правок App.

Изоляция рук друг от друга: каждый слот параллельности работает в своём клоне песочницы, `src/pages` чистится перед каждым прогоном.

## Руки

Различаются **только** доступом к инструментам; модель, задачи, промпт, обстановка одинаковы.

| Рука | MCP | `Read`/`Grep`/`Glob` | Что меряет |
|---|---|---|---|
| `pkg` | нет | да (песочница) | как потребитель живёт сегодня |
| `pkg-mcp` | да | нет | достаточен ли индекс сам по себе |
| `pkg-both` | да | да (песочница) | реалистичная конфигурация |
| `src` / `src-mcp` | нет / да | весь монорепо | вспомогательный стенд: нужен ли MCP разработчикам самой библиотеки |
| `pkg-mcp-before` | да (сервер из коммита до T1) | нет | базовая линия «до правок» (`ab/prepare-before.mjs`) |

## Метрики

1. **`tsc проходит`** — доля ответов без единой диагностики. Компиляция настоящая и в песочнице: `@daisforge/ui` резолвится в установленный пакет и его `.d.ts` — ровно то, против чего собирает код потребитель.
2. **`Выдумано на задачу`** — экспорт или проп, которого нет ни в пакете, ни в индексе:
   - `unknown-import` — `TS2307`/`TS2305`/`TS2724`/`TS2614`/`TS2613`;
   - `unknown-prop` — `TS2322`/`TS2339`/`TS2353`/`TS2559`/`TS2769`/`TS2561`, если в тексте (включая **отступные строки-продолжения**, где tsc и прячет суть перегрузочной ошибки) есть «Property 'X' does not exist» или «Object literal may only specify known properties».
3. **`Тулов до кода`** — вызовов инструментов до `Write` файла-ответа. Это то число, которое MCP обязан снижать.
4. **`Профильный компонент`** — взял ли агент хотя бы один компонент из `expect` задачи. Прямая проверка пользы каталога (T2/T9): нашёл ли он нужное вообще.

Отдельно, **не в счёт агенту**:

- **`index-drift`** — проп или экспорт, который индекс обещает, а в установленном пакете его нет. Меряется заранее (`ab/drift.mjs`, настоящий тайпчекер по всем 5086 пропсам индекса) и вычитается: агент не выдумывал, он поверил индексу. Это отдельная находка замера — в неё, например, попал `DataEditor`, который индекс отдаёт с `importPath: '@daisforge/ui'`, хотя из барреля он не экспортируется (известный дефект, `ARCHITECTURE.md` §5).
- **`type-mismatch`** — настоящий компонент и настоящий проп, но неверно типизированное значение. Провал `tsc`, но не выдумка.

Скорер поверяется на эталонах без запуска агента:

```bash
npm run mcp:ab:selfcheck   # честный файл обязан пройти, поддельный — дать обе выдумки
```

## Полезные ключи

```bash
node ab/run.mjs --arms pkg,pkg-mcp --tasks drawer-table --force   # переснять отдельное
node ab/run.mjs --model haiku --concurrency 5 --budget 0.3
node ab/score.mjs --arms pkg,pkg-mcp                              # пересчёт без прогонов
node ab/assemble-app.mjs --arm pkg --only-passing                 # приложение из ответов руки
node ab/prepare-consumer.mjs --ui-source local                    # пакет из локальной сборки
```

- прогоны **резюмируемы**: задача с готовым транскриптом не переснимается без `--force`;
- `--budget` (по умолчанию `$0.5`) — потолок на прогон, `--timeout` (по умолчанию 420 с) — тоже;
- агенту выдаётся только `Write` плюс инструменты его руки; писать он может лишь в свой клон песочницы.

## Задачи

`tasks.json` — 20 задач четырёх уровней: `single` (12), `form` (3, react-hook-form + zod + `useFieldArray`), `table` (2, на `TableCanvas`), `composition` (3). Таблицы везде требуются на `TableCanvas` — это рекомендованный библиотекой путь (`CLAUDE.md`), а `Table` помечен `legacy`/`supersededBy` (T9). Поля `hint` и `expect` агенту не показываются.
