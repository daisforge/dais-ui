# Тесты перерисовки TableCanvas

Проверяют, что частичная перерисовка таблицы (наведение, выделение, прокрутка)
рисует ровно то же, что и кадр целиком, и что она действительно частичная.

## Как это работает

Playwright открывает историю-стенд, водит по таблице настоящей мышью и
клавиатурой и после каждого шага делает две вещи:

1. Сверяет холсты тела и шапки с кадром целиком. Пиксели снимаются в самой
   странице, таблица перерисовывается целиком той же функцией, что и перед
   снимками, пиксели снимаются ещё раз и сравниваются. Эталонов нет: сравнение
   идёт в одном браузере в один момент, поэтому шрифты, видеокарта и браузер на
   него не влияют.
2. Смотрит журнал кадров glide (`experimental.onFrameDrawn`): каким путём был
   нарисован кадр (`full`, `blit`, `selection`, `damage`), трогал ли он шапку и
   какая доля тела перерисована. Иначе откат на кадр целиком прошёл бы незаметно:
   картинка та же, но вся экономия потеряна.

При расхождении в отчёт попадают три картинки: частичный кадр, кадр целиком и
разница, плюс координаты области и число пикселей.

Стенды лежат в `src/stories/TableCanvas/TableCanvas.Redraw`: обычная таблица,
закреплённые колонки и строки, объединённые ячейки, выделение снаружи. Их PNG не
снимаются. Сценарии в `specs/`, общие действия и проверки в `grid.ts`.

`specs/self-check.spec.ts` проверяет сам механизм: сравнение замечает один
пиксель на каждом холсте, журнал кадров ведётся. `specs/random.spec.ts` гоняет
случайные серии действий с фиксированным зерном.

## Запуск

В Docker, тот же образ, что у снимков (браузеры, шрифты, собранный Storybook):

```
npm run redraw:test
npm run redraw:test -- hover                 # файлы сценариев по регулярному выражению
npm run redraw:test -- --project chromium    # один проект
npm run redraw:test -- --grep наведение      # по названию теста
```

Локально, без Docker. Нужны браузеры Playwright (`npx playwright install`).
Тестовый стенд Storybook (сборка в `dist/storybook` с точками входа для тестов)
собирается сам, если его ещё нет; после правок кода пересобрать его `--build`:

```
npm run redraw:test:local
npm run redraw:test:local -- --build
npm run redraw:test:local -- --project chromium --repeat-each 3
```

Против запущенного Storybook (dev-сервер нужно поднять с
`STORYBOOK_SCREENSHOT_TEST=1`, иначе в странице нет полной перерисовки):

```
REDRAW_URL=http://localhost:4400 npm run redraw:test:local
```

Отчёт каждого запуска в `artifacts/redraw/<время>/report/index.html`, там же
трассы упавших тестов.

## Проекты

- `chromium`: сверка после каждого шага.
- `chromium-accumulate`: одна сверка в конце серии. Ловит следы, которые копятся
  несколько шагов и стираются полной перерисовкой между шагами.
- `chromium-dpr-1.25`, `chromium-dpr-2`, `chromium-dpr-0.8`: настоящий масштаб
  устройства через флаг браузера, в том числе меньше единицы.
- `firefox`, `webkit`.

## Свой браузер

`REDRAW_BROWSER=<путь>` запускает chromium-проекты на этом браузере (любой на
основе Chromium), Firefox и WebKit при этом не запускаются:

```
REDRAW_BROWSER="C:\Program Files\SberBrowser\Application\sberbrowser.exe" npm run redraw:test:local
REDRAW_BROWSER=/opt/Sberbrowser/sberbrowser/sberbrowser npm run redraw:test:local
```

## Переменные

- `REDRAW_URL`: готовый Storybook вместо сборки в `dist/storybook`.
- `REDRAW_PORT`: порт встроенного сервера, по умолчанию 4401.
- `REDRAW_BROWSER`: путь к браузеру.
- `REDRAW_SEED`, `REDRAW_RANDOM_STEPS`: зерно и длина случайных серий.
- `REDRAW_ARTIFACTS_DIR`: каталог отчёта.

## Как добавить сценарий

Шаг описывается через `grid.step(название, действие, ожидание)`: действие
выполняется, таблица успокаивается, кадры шага проверяются по ожиданию, затем
сверка с полным кадром (в проекте накопления она откладывается до
`grid.finish()`). Ожидание задаёт допустимые виды кадров, перерисовку шапки и
наибольшую долю перерисованного тела. Координаты ячеек: колонка без служебных,
строка; `-1` это шапка и колонка нумерации.
