# GridDND

Компонент для создания адаптивных сеток с поддержкой перетаскивания элементов и автоматическим переносом между брейкпоинтами.

## Ключевые особенности

- Единый пропс `items` как источник истины (без сложной инициализации)
- Три типа виджетов: `s` (1x1), `m` (2x1), `l` (2x2) с автоматической адаптацией
- Мутации через `ref.api`: добавление, удаление, смена типа, переупорядочивание
- Кастомные брейкпоинты и колонки
- Алгоритм `packByItemsOrder` для предсказуемого размещения
- Drag Handle и No-Drag Zones через CSS-классы

## Быстрый старт

### Базовое использование

```tsx
import { GridDND } from '@dais-ui/ui-kit';

const MyGrid = () => (
  <GridDND
    items={[
      { id: 'widget-1', type: 's' },
      { id: 'widget-2', type: 'm' },
      { id: 'widget-3', type: 'l' },
    ]}
  >
    {(item, onRemove) => (
      <div key={item.id}>
        <h3>Виджет {item.id}</h3>
        <button onClick={onRemove}>Удалить</button>
      </div>
    )}
  </GridDND>
);
```

### Единый источник истины

Пропс `items` передаётся **один раз** — это начальный снимок (порядок + типы).
Все runtime-мутации идут через `ref.api.*`. После маунта изменения `items`
в props игнорируются — это сделано специально, чтобы не было гонок с
пользовательскими действиями (D&D, add/remove).

```tsx
// ПРАВИЛЬНО — передаём один раз при маунте
<GridDND items={initialItems} />

// НЕПРАВИЛЬНО — изменения после маунта не подхватятся
<GridDND items={dynamicItems} />
```

### Мутации через `ref.api`

- **Добавить** — `api.addItem({ id, type }, index?)`
- **Удалить** — `api.removeItem(id)`
- **Изменить type** — `api.setItemType(id, 's' | 'm' | 'l')`
- **Переупорядочить** — `api.setOrder(ids)`
- **Получить состояние** — `api.getOrder()`, `api.getOrderDetailed()`, `api.getCurrentLayout()`, `api.getAllLayouts()`

```tsx
const gridRef = useRef<GridDNDRef>(null);

// Пример: «вырастить» виджет w1 до L
gridRef.current?.api.setItemType('w1', 'l');
```

### Для виджета, который сам меняет свой размер

Render-prop получает 3 аргумента: `(item, onRemove, onResize)`. Функции
`onRemove` и `onResize` уже пре-каррированы к `item.id` — под капотом вызывают
`api.removeItem(id)` и `api.setItemType(id, type)` соответственно.

```tsx
<GridDND items={initialItems}>
  {(item, onRemove, onResize) => (
    <GridDND.ItemWrapper item={item}>
      <MyWidget
        type={item.type}
        onResize={onResize} // onResize('l') — виджет сам себя растит
        onRemove={onRemove}
      />
    </GridDND.ItemWrapper>
  )}
</GridDND>
```

> Важно: React-ключ по `item.id` стабилен, поэтому при `setItemType`/reflow
> **React-инстанс виджета не размонтируется** — внутренний `useState`,
> ссылки, фокусы сохраняются. Визуально меняется только размер ячейки.

## Типы виджетов и размеры

Компонент поддерживает три типа виджетов:

- **'s'** (small) - 1x1 ячейка
- **'m'** (medium) - 2x1 ячейки
- **'l'** (large) - 2x2 ячейки

Размеры автоматически адаптируются под количество колонок в брейкпоинте.

## Адаптивность и брейкпоинты

### Стандартные брейкпоинты

```ts
{
  lg: 1857,  // 6 колонок
  md: 1377,  // 6 колонок
  sm: 1145,  // 5 колонок
  xs: 913,   // 4 колонки
  xxs: 0     // 4 колонки
}
```

### Кастомные брейкпоинты

```tsx
<GridDND
  breakpoints={{ desktop: 1440, tablet: 1024, mobile: 768 }}
  cols={{ desktop: 8, tablet: 6, mobile: 4 }}
  rowHeights={{ desktop: 200, tablet: 150, mobile: 100 }}
/>
```

## Алгоритмы размещения

### 1. Алгоритм packByItemsOrder

Основной алгоритм размещения элементов в порядке их следования:

```tsx
// Псевдокод алгоритма
function packByItemsOrder(order, sizes, cols) {
  // 1. Создаётся виртуальная сетка для отслеживания занятых ячеек
  // 2. Для каждого элемента в порядке order:
  // - Определяются размеры элемента (w x h)
  // - Поиск начинается с текущей "границы чтения" (fy, fx)
  // - Сначала проверяется текущая строка fy, начиная с позиции fx
  // - Если не помещается - ищется ниже, начиная со строки fy+1
  // 3. Найденное место занимается в виртуальной сетке
  // 4. "Граница чтения" обновляется для следующего элемента
}
```

Ключевые особенности алгоритма:

- Сохраняет порядок чтения (слева направо, сверху вниз)
- После перехода на новую строку возврат к предыдущим строкам невозможен
- Оптимизирован для минимального количества "дырок" в сетке
- Гарантирует предсказуемое расположение при изменении порядка элементов

### 2. Алгоритм первого подходящего места (placeRectFirstFit)

При добавлении новых элементов используется алгоритм First Fit:

- Создается виртуальная карта занятых ячеек
- Поиск ведется от стартовой позиции (0,0 по умолчанию)
- Находится первое свободное место нужного размера

## Управление перетаскиванием

### Drag Handle

Для создания области перетаскивания добавьте класс `grid-dnd__drag-handle`:

```tsx
<div className="grid-dnd__drag-handle">Перетаскивайте за эту область</div>
```

### No-Drag Zones

Чтобы запретить перетаскивание за определенные элементы, используйте класс `grid-dnd__no-drag`:

```tsx
<button className="grid-dnd__no-drag">
  Эта кнопка не будет запускать перетаскивание
</button>
```

### Кастомные handles

```tsx
<GridDND draggableHandle=".my-drag-handle">
  <div className="my-drag-handle">Перетаскивайте меня</div>
</GridDND>
```

### Конфигурация отступов

```tsx
<GridDND
  margin={[16, 16]} // Отступы между элементами [x, y]
  containerPadding={[24, 24]} // Внутренние отступы контейнера
/>
```

### Настройка поведения

```tsx
<GridDND
  isDraggable={true} // Включить перетаскивание
  isResizable={false} // Отключить изменение размера
  preventCollision={true} // Предотвращать пересечения
  compactType="vertical" // Тип сжатия: 'vertical', 'horizontal', null
  verticalCompact={true} // Вертикальное сжатие
/>
```
