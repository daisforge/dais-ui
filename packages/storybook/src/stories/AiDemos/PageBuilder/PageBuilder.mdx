# AI-конструктор страниц

Слева чат, по центру холст, справа свойства, слои и палитра. Экран описывается
словами («собери реестр платежей с фильтрами по дате и статусу»), агент собирает
его из компонентов `@daisforge/ui` по шаблонам и дизайн-гайдам. Дальше страницу
правят словами, кликом по элементу и в панели свойств, а на выходе получают TSX
или JSON.

Это прототип: **LLM имитируется** правилами по ключевым словам. По-настоящему
работают рендер настоящими компонентами, панель свойств из MCP-индекса,
проверка правил гайдов с автоисправлением и генерация TSX.

- [Демо](?path=/story/ai-демо-конструктор-страниц--demo): свободный режим.
- [Автосценарий](?path=/story/ai-демо-конструктор-страниц--autoplay): реестр, правки, форма.

## Три уровня знаний агента

```
3. ШАБЛОНЫ ЭКРАНОВ      реестр, карточка, форма, дашборд, пустой реестр
                        агент выбирает шаблон и заполняет слоты, а не расставляет каждый элемент
2. ПРАВИЛА КОМПОНОВКИ   из гайдов: одна акцентная кнопка, не больше трёх видимых действий,
                        деструктив в меню, submit формы внизу, таблица без гор. скролла
1. КОМПОНЕНТЫ И ПРОПСЫ  MCP-индекс: 245 компонентов, типы пропсов, импорты
```

Уровень 1 уже есть. Уровень 2 есть в виде текста для людей
(`packages/docs/design/guides`), MCP его не отдаёт. Уровня 3 нет: в демо он
лежит в `model/templates.ts`, в продукте это TSX-stories шаблонов.

## Что нужно сделать

1. **Гайды в MCP**: инструменты `search_guides` / `get_guide`, жёсткие правила — в проверки. ~1 неделя.
2. **Шаблоны экранов**: 6–7 шаблонов как TSX-stories со слотами (реестр, карточка, форма,
   master-detail на `SplitView`, мастер на `Steps`, дашборд, пустое состояние и ошибка).
   Делают дизайнер + разработчик. ~2–3 недели.
3. **MCP-инструменты шаблонов**: `search_templates`, `get_template`. Индексер уже есть.
4. **Action Bot Panel** как компонент библиотеки: в гайде есть, в коде нет (в демо — пресет `ActionBar`).
5. **Бэкенд-прокси к LLM**: Storybook статический, ключ в браузер класть нельзя.
6. **Приложение конструктора**: сохранение проектов, шаринг, drag-and-drop поверх того же дерева
   (оценить Puck), экспорт HTML через runtime из демо отчётов.

## Риски

- Качество раскладки зависит от шаблонов и гайдов, а не от модели: без уровней 2–3 агент
  собирает «правильные компоненты в случайном порядке».
- Компоненты с функциями в пропсах (колонки `TableCanvas`, рендеры) не сериализуются:
  нужен JSON-срез их API.
- Логика (состояние, запросы, валидация) — вне объёма: это прототип и каркас, не low-code.
