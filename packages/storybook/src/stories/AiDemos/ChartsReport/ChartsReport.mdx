# AI-отчёты с графиками

Пользователь прикрепляет в чате AI-агента файл с данными, описывает словами,
что за что отвечает и какой отчёт нужен. Агент собирает отчёт с графиками
и отдаёт один HTML-файл, который можно переслать руководству.

Это прототип взаимодействия. **Бэкенда и LLM в нём нет**: ответы модели
имитируются правилами по ключевым словам, графики рисует заглушка на месте
Charts UI. Разбор файла, проверка спецификации, расчёт цифр и экспорт
HTML работают по-настоящему, в браузере.

- [Демо](?path=/story/ai-демо-отчёты-с-графиками--demo): свой CSV или пример, запросы словами.
- [Автосценарий](?path=/story/ai-демо-отчёты-с-графиками--autoplay): сообщения отправляются сами, удобно для показа.

## Зачем

Пользователи хотят видеть свои данные в виде понятных графиков и показывать
такие отчёты выше. Сейчас это ручная работа в Excel или BI. Агент снимает
её целиком: файл + одна фраза → готовый отчёт в фирменном стиле.

## Сценарий

1. Прикрепить CSV (кнопка с документом в поле ввода) или взять пример.
2. Агент разбирает файл и показывает, какие колонки и типы нашёл.
3. Описать отчёт: «покажи динамику выручки по месяцам в разрезе регионов и добавь итоговые KPI».
4. Уточнять словами: «сделай первый график столбцами», «оставь только Москву и Сибирь»,
   «добавь таблицу», «назови отчёт «…»».
5. Скачать HTML или открыть его в новой вкладке. Вкладки «Спецификация» и «Данные»
   показывают, что модель получила на вход и что вернула.

## Как это устроено

```
Файл (CSV/XLSX)
  │
  ▼
Бэкенд: разбор и профиль (колонки, типы, диапазоны, 3 примера значений)
  │        строки данных в LLM не уходят
  ▼
LLM + MCP Charts UI ── list_charts / get_chart_schema / get_report_template
  │  возвращает только ReportSpec (JSON, ~1 КБ)
  ▼
Проверка спецификации ── ошибки → обратно в LLM (1–2 круга)
  │
  ▼
render_report: runtime Charts UI считает цифры по ВСЕМ строкам
  │
  ▼
Предпросмотр в чате (sandbox iframe) + скачать HTML / PDF / PNG
  │
  └── правка словами → patch_report_spec → перерисовка
```

Три решения, на которых держится подход:

- **Модель не пишет HTML и не считает цифры.** Она выбирает блоки, колонки
  и агрегации. Цифры считает код, поэтому они совпадают с исходным файлом.
- **Данные не уходят в модель.** Только схема и несколько значений на колонку.
  Это снимает большую часть вопросов ИБ и ограничений на размер файла.
- **Один контракт — ReportSpec.** Его генерирует модель, проверяет валидатор,
  рендерит runtime. Замена имитации на настоящую LLM не трогает рендер и экспорт.

## Контракт ReportSpec

Тип и проверка — в [`engine/spec.ts`](https://github.com/daisforge/dais-ui/blob/develop/packages/storybook/src/stories/AiDemos/ChartsReport/engine/spec.ts).
Пример после запроса «покажи динамику выручки по месяцам в разрезе регионов и добавь итоговые KPI»:

```json
{
  "version": 1,
  "title": "Выручка по месяцам в разрезе регионов",
  "dataset": "продажи_2025.csv",
  "filters": [],
  "blocks": [
    {
      "kind": "kpi",
      "id": "kpi-1",
      "items": [
        {
          "label": "Выручка, млн ₽, итого",
          "measure": { "column": "Выручка, млн ₽", "agg": "sum" }
        },
        {
          "label": "Сделки, итого",
          "measure": { "column": "Сделки", "agg": "sum" }
        },
        {
          "label": "Строк в выборке",
          "measure": { "column": "Месяц", "agg": "count" }
        }
      ]
    },
    {
      "kind": "chart",
      "id": "chart-2",
      "title": "Выручка по месяцам в разрезе регионов",
      "chart": "line",
      "x": { "column": "Месяц", "timeUnit": "month" },
      "measures": [{ "column": "Выручка, млн ₽", "agg": "sum" }],
      "series": "Регион"
    }
  ]
}
```

Блоки: `kpi`, `chart` (`bar` / `line` / `area` / `pie`), `table`. Фильтры —
по значениям категорий. Когда Charts UI приедет, перечень типов и их опции
берутся из его схемы, а не из этого файла.

## Что нужно сделать

### 1. Charts UI (библиотека графиков)

- Декларативный API: график целиком описывается JSON-конфигом, без функций в пропсах.
- Zod-схема конфигов из пакета: её же использует валидатор спецификации и MCP.
- Runtime-бандл (IIFE, всё внутри) для вставки в один HTML-файл. Шрифты встроены
  или с fallback: файл должен открываться офлайн из почты.
- Палитра и токены в теме Plasma, светлая и тёмная, проверенные на различимость.
- Подключение в демо: заменить компоненты в `ChartRenderer`
  ([`charts-stub/Charts.tsx`](https://github.com/daisforge/dais-ui/blob/develop/packages/storybook/src/stories/AiDemos/ChartsReport/charts-stub/Charts.tsx)),
  контракт `ChartData` остаётся тем же.

### 2. MCP

- Раздел Charts UI в индексе: типы графиков, какие данные под какой тип,
  схема опций, примеры. Собирается тем же индексером, что и компоненты.
- Инструменты: `list_charts`, `get_chart_schema`, `get_report_template`
  (шаблоны отчётов: «для руководства», «план-факт», «динамика»).
- HTTP-транспорт (Streamable HTTP) или импорт инструментов библиотекой:
  сейчас сервер работает только через stdio, это годится для локальных агентов,
  а не для бэкенда чата.

- Разбор CSV/XLSX: объединённые ячейки, шапка в несколько строк, даты в разных
  форматах, числа с пробелами и запятой.
- Оркестрация LLM: tool-calling, лимит кругов самоисправления, таймауты.

  (в репозитории уже есть Docker с Chromium для скриншотных тестов).
- Хранение файлов и отчётов, срок жизни, права доступа.

### 4. Фронт

- Чат уже есть: `AiAgentPopup`, `AiAgentSurface`, `AiAgentInput`.
- Вложение файла в поле ввода, отображение шагов агента, предпросмотр
  отчёта в sandbox iframe, кнопки «Скачать» и «Открыть».

### 5. ИБ и данные

- Согласовать, что именно уходит в модель: только схема или ещё выборка строк.
- Какая модель и где она работает.
- Срок хранения загруженных файлов.

## Риски

- Грязные Excel-файлы: основной источник ошибок, нужен набор реальных файлов для проверки.
- Качество понимания запроса: нужен набор из 30–50 типовых запросов
  и замер, как в A/B-стенде MCP (`packages/mcp-server/ab`).
- Размер HTML с runtime-бандлом и встроенными шрифтами.
- Ограничения ИБ на отправку данных в модель.

## Открытые вопросы

- На чём построен Charts UI и есть ли у него декларативный конфиг.
- Чей бэкенд у чата и какая модель.
- Нужен ли отчёт офлайн (вложение в почту) или подойдёт ссылка.
