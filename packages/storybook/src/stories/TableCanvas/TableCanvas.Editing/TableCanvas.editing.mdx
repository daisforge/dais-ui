# Editing (TableCanvas)

**tableConfig.editing + columnConfig.editingCell**

Режим редактирования данных в ячейках таблицы. Условие активации — наличие свойства `editing` в `tableConfig`. Также необходимо сконфигурировать колонки через `editingCell`.

## Ключевые особенности

- Управление режимом редактирования через `enabled` / `defaultEnabled`
- Callback-и при включении, сохранении и отмене (`onEnableEditing`, `onSave`, `onCancel`)
- Контроль редактируемости строк через `rowEditable`
- Поддержка дочерних строк через `subRowsKey`
- Кнопки управления в controlBlock (`showButtons`)
- `editingCell.component` рендерит React-компонент поверх таблицы; `Canvas.*` элементы используйте только в `renderCell`, `renderHeaderCell` и `renderSummaryCell`

## Жизненный цикл

1. Пользователь нажимает кнопку «Редактирование» → вызывается `onEnableEditing`
2. При изменении ячейки → вызывается `onRowsChange` с данными об изменённых строках
3. При нажатии «Сохранить» → вызывается `onSave`
4. При нажатии «Отменить» → вызывается `onCancel`

## Управление состоянием

- **`defaultEnabled`** — начальное состояние (внутренний стейт)
- **`enabled: boolean`** — полностью внешнее управление (без переключения в таблице)
- **`enabled: [boolean, setState]`** — внешний стейт с возможностью переключения в таблице

## Особенности

- `onRowsChange` — обязательный callback, получает обновлённые строки и метаданные (индексы, колонка, before/after)
- `subRowsKey` — обязателен, если дочерние строки хранятся не под ключом `subRows`. Поддерживает вложенность через точку (например, `'data.children'`)
- `showButtons` — по умолчанию `true`, управляет видимостью кнопок в controlBlock

## Управление кнопками (buttons)

Через `editing.buttons` можно передать пропсы кнопкам `save`, `cancel` и `edit`. `onClick` исключён — обработчики задаются через `onSave` / `onCancel` / `onEnableEditing`.

```tsx
editing: {
  buttons: {
    save: { disabled: isSaving, isLoading: isSaving },
    cancel: { disabled: isSaving },
  },
  onSave(disableEditorMode) {
    setIsSaving(true);
    api.save(rows).finally(() => {
      setIsSaving(false);
      disableEditorMode();
    });
  },
}
```

## Ошибки ячеек

Ошибку ячейки задаёт колонка. Если `error.value` вернула `true`, у ячейки появляется красная рамка. Рамки работают только в режиме редактирования и считаются только для видимой части таблицы, поэтому подходят для больших данных.

```tsx
{
  key: 'amount',
  name: 'Сумма',
  editingCell: {
    component: 'inputNumber',
    error: {
      value: (row) => row.amount > row.limit,
    },
  },
}
```

Чтобы при наведении на такую ячейку показывалась подсказка, добавьте `error.tooltip`. Можно вернуть строку или объект с настройками (`placement`, `maxWidth`, задержки). Функция вызывается только при наведении и только для ячеек с ошибкой.

```tsx
error: {
  value: (row) => row.amount > row.limit,
  tooltip: (row) => ({
    text: `Сумма ${row.amount} больше лимита ${row.limit}`,
    placement: 'right',
  }),
}
```

Подсказка ошибки показывается вместо `cellTooltip` колонки и не требует `tableConfig.tooltip.enabled`.

## Столбец с индикатором ошибок

Чтобы пользователь видел, в каких строках есть ошибки, включите служебный столбец через `editing.rowErrors`. Он встаёт правее нумерации и чекбоксов, и у каждой строки, где есть хотя бы одна ячейка с ошибкой, показывает красный треугольник. При наведении на него выводится «Ошибок в строке: N».

```tsx
editing: {
  rowKeyGetter: (row) => row.id,
  onRowsChange: setRows,
  rowErrors: true,
}
```

Как ведёт себя столбец:

- появляется при входе в режим редактирования и исчезает при выходе из него;
- ширина и размер иконки зависят от `rowSize`;
- у него пустой заголовок, его нельзя растянуть, выделить, переставить или скрыть через управление столбцами;
- число ошибок считается по всем колонкам строки, а не только по видимым.

Если нужны только рамки без столбца, передайте объект с `indicatorColumn: false`. Это удобно, когда столбец включают и выключают по кнопке.

```tsx
rowErrors: {
  indicatorColumn: false;
}
```

## Ошибка всей строки

Иногда ошибка относится не к отдельной ячейке, а к строке целиком, например когда документ отклонён. Для этого передайте `rowErrors.isErrorRow`. У таких строк вместо рамок на ячейках рисуется одна рамка по всей ширине данных, а в столбце-индикаторе тоже горит иконка.

```tsx
rowErrors: {
  isErrorRow: (row) => row.status === 'rejected',
}
```

Режимы можно смешивать: одни строки помечаются целиком, другие поячеечно через `error.value`. Подсказки по умолчанию у строки целиком нет, её задают через `rowErrors.tooltip`.

## Свой текст подсказки у индикатора

`rowErrors.tooltip` заменяет текст подсказки у иконки. В функцию приходит объект с полями `row`, `treeLevel`, `errorCellsCount`, `errorColumnKeys` и `isErrorRow`. Вернуть можно строку, объект с настройками или `null`, если подсказка не нужна. По умолчанию подсказка стоит над иконкой и уходит вправо от неё (`placement: 'top-start'`), другое размещение задаётся в объекте.

```tsx
rowErrors: {
  isErrorRow: (row) => row.status === 'rejected',
  tooltip: ({ isErrorRow, errorCellsCount }) =>
    isErrorRow ? 'Документ отклонён' : `Ошибок в строке: ${errorCellsCount}`,
}
```

Типы `RowErrorsConfig` и `RowErrorsInfo` описаны в разделе [API](/docs/локальные-компоненты-tablecanvas-editing-api--docs).

## Асинхронное сохранение и ошибки с сервера

Таблица не решает сама, можно ли выходить из режима правки. В `onSave` и `onCancel` приходит функция `disableEditorMode`, и режим выключается только после её вызова. Поэтому проверка на сервере встраивается без дополнительных настроек: колбэк делает запрос, ждёт ответ и либо выключает режим, либо остаётся в нём и показывает ошибки.

Порядок действий такой.

- На время запроса кнопке «Сохранить» передаются `isLoading` и `disabled` через `editing.buttons.save`, кнопке «Отменить» `disabled`. При сжатии контрол-блока кнопки правки остаются на месте в виде иконок, спиннер виден и там.
- Ошибки из ответа сервера складываются в стейт приложения по ключу строки и колонке. В `editingCell.error.value` колонка читает этот стейт, поэтому для таблицы серверная ошибка ничем не отличается от ошибки валидации на фронте: рамка, подсказка и индикатор в столбце появляются сами.
- Если ошибки есть, `disableEditorMode` не вызывается. Таблица остаётся в режиме правки, а приложение показывает уведомление или модальное окно.
- Столбец-индикатор можно включать только при наличии ошибок: `rowErrors: errors.length > 0 ? true : undefined`. До ответа сервера таблица про ошибки не знает, а после ответа столбец появится вместе с подсветкой. Кому сдвиг строк на ширину столбца мешает, держит `rowErrors` включённым постоянно.

```tsx
editing: {
  buttons: {
    save: { isLoading: saving, disabled: saving },
    cancel: { disabled: saving },
  },
  rowErrors: serverErrors.length > 0 ? true : undefined,
  onSave: async (disableEditorMode) => {
    setSaving(true);
    const errors = await api.save(rows);
    setSaving(false);
    setServerErrors(errors);
    if (errors.length > 0) {
      showNotification(`Ошибок: ${errors.length}, исправьте подсвеченные ячейки`);
      return;
    }
    disableEditorMode();
  },
}
```

Таблица проверяет ошибки только у строк в окне видимости и ничего не знает о строках на других страницах пагинации. Решение «есть ли ошибки вообще» всегда за приложением: оно хранит список ошибок по ключам строк и в `onSave` проверяет его целиком, а не то, что сейчас на экране. Если ошибки на другой странице, об этом стоит сказать в уведомлении.
