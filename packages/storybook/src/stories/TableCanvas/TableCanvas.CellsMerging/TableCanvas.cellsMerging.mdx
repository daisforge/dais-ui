# CellsMerging (TableCanvas)

Объединение ячеек тела таблицы: по строкам (rowSpan), по колонкам (colSpan) и
прямоугольными блоками. Несколько одинаковых ячеек рисуются одной большой, а всё
взаимодействие — клики, выделение, навигация, копирование, вставка, протяжка,
редактирование — обращается с блоком как с одной ячейкой.

Эта страница — обзор: как выбрать способ и с чего начать, плюс живые примеры.
Подробности (совмещение способов, работа с деревом, выравнивание, сводные
ограничения) — в
[Справочнике](?path=/docs/локальные-компоненты-tablecanvas-cellsmerging-справочник--docs),
типы — в
[API](?path=/docs/локальные-компоненты-tablecanvas-cellsmerging-api--docs).

## Как это устроено

Главная идея простая: объединение — это способ показа, а не способ хранения.

- В данных значение повторяется в каждой строке блока. Если «Отдел А» тянется на
  три строки, то во всех трёх строках в поле отдела записано «Отдел А».
- Таблица замечает повторы (или получает границы блока явно) и вместо трёх
  одинаковых ячеек рисует одну высокую. Содержимое берётся из верхней-левой
  ячейки блока.
- Данные при этом не меняются. Уберите объединение — увидите те же строки с теми
  же значениями.

Отсюда следует и поведение, знакомое по Excel: клик в любую точку блока выделяет
блок целиком, правка блока меняет значение во всех его строках, копирование
отдаёт значение один раз.

## Три способа включить объединение

Механика под всеми способами одна. Отличие — кто вычисляет границы блоков:
потребитель или таблица. Способы можно совмещать в одной таблице — правила в
Справочнике, глава «Если включено несколько способов сразу».

### 1. mergeCells.mergedCellsRegions — блоки, заданные снаружи

«Слей вот эти конкретные ячейки». Список блоков по стабильным ключам строк и
колонок; списком владеет потребитель, как выделением. Таблица переводит ключи в
текущие видимые позиции. Если сортировка, перестановка или скрытие колонки
разорвали блок — он не рисуется (как ограничение сортировки в Excel).

```tsx
tableConfig={{
  mergeCells: {
    mergedCellsRegions: [
      { rowKeys: ['r1', 'r2'], colKeys: ['dept'] },
      { rowKeys: ['r4', 'r5'], colKeys: ['plan', 'fact'] }, // прямоугольник 2×2
    ],
    rowKeyGetter: (row) => row.id,
  },
}}
```

Примеры — стори с префиксом `mergedCellsRegions:` ниже.

### 2. mergeCells.mergeByCellValues — по одинаковым значениям

«В этих колонках сливай подряд идущие одинаковые значения». Границы блоков
таблица вычисляет сама из данных; после сортировки или фильтра блоки
пересобираются.

```tsx
tableConfig={{
  mergeCells: {
    mergeByCellValues: [
      'dept',                                             // по значению колонки
      { colKey: 'role', value: (row) => row.roleGroup },  // по своей функции
    ],
  },
}}
```

Одинаковые названия в разных ветках иерархии могут ложно слиться — лечится
составным ключом, разбор в Справочнике, глава «Объединение по значению: где
проходит граница». Примеры — стори с префиксом `mergeByCellValues:` ниже.

### 3. Merged-виды группировки и subRows — полный автомат

Потребитель включает вид — всю работу с блоками делает таблица: строки
упорядочиваются по группам, колонки уровней сливаются по границам групп, чекбокс
и нумерация работают по верхней группе.

Через группировку (структуру задают значения группирующих колонок):

```tsx
tableConfig={{
  rowsGrouping: {
    view: 'merged',
    groupByState: [groupBy, setGroupBy], // например ['dept', 'role']
    rowKeyGetter: (row) => row.id,
  },
}}
```

Через subRows (структуру задаёт готовое дерево потребителя):

```tsx
tableConfig={{
  subRows: {
    view: 'merged',
    mergedColumns: ['dept', 'role'], // колонки уровней дерева
    getSubRows: (row) => row.children,
    rowKeyGetter: (row) => row.id,
  },
}}
```

Примеры — «subRows: дерево с пагинацией» и «rowsGrouping: группировка
пользователем» в конце страницы.

## Какой способ выбрать

Картинка у способов похожая, поэтому выбирать стоит не по внешнему виду, а по
тому, кто владеет данными и что нужно пользователю.

### Дерево приходит с сервера, нужна постраничная загрузка — subRows

Если данные уже иерархические (дивизион, управление, команда, сотрудники) и
приходят от сервера частями, берите `subRows` с `view: 'merged'`. Дерево остаётся
у вас: вы отдаёте таблице страницу дерева, она разворачивает её в строки и сама
сливает колонки-предки. Именно поэтому здесь работает пагинация по верхним
блокам — таблице не нужно видеть все данные сразу.

Обратная сторона: раз данными владеете вы, то поиск, сортировка и фильтрация
дерева — тоже на вашей стороне. Формат дерева, пагинация и возврат правок —
в Справочнике, глава «Дерево через subRows».

### Плоские строки, пользователь сам выбирает группировку — rowsGrouping

Если строки плоские, а пользователь должен на лету решать, по каким колонкам
группировать, — берите `rowsGrouping` с `view: 'merged'`. Состав группировки живёт
в `groupByState`, а с настройкой `groupButton` в блоке управления появляется
кнопка: пользователь сам выбирает колонки, таблица пересобирает блоки. Встроенные
поиск, сортировка и фильтры работают — таблица применяет их до сборки групп.

Обратная сторона: пагинации в этом виде нет — таблице нужны все строки сразу.
Не действует и всё, что привязано к строкам-групп и шевронам дерева
(`groupedColumnProps`, `renderGroupCell`, `expandAllBtn`) — полный список в
Справочнике, глава «Что не работает и почему».

### Плоские строки, группировка фиксированная, всё считает сервер — mergeByCellValues

Если структура известна заранее и не меняется пользователем, а данные (включая
страницы, сортировку и фильтры) готовит сервер, — самый прямой путь это
`mergeByCellValues`. Вы упорядочиваете строки как нужно, таблица сливает соседние
одинаковые значения. Никакой лишней механики: ни кнопок, ни дерева.

### Отдельные ручные блоки — mergedCellsRegions

Шапки секций внутри таблицы, нестандартные прямоугольники, объединение по кнопке
или из контекстного меню — всё, что не выводится из значений, делается регионами.
Потребитель добавляет блок в свой список — таблица его рисует.

## Полные примеры

Три больших примера ниже собраны как заготовки для продуктов: в каждом —
объединение ячеек в связке с поиском, сортировкой, фильтрами, пагинацией,
редактированием и выделением. Различаются они тем, кто владеет данными, поэтому
и код обвязки разный. Полный код каждого примера открывается кнопкой «Show code»
и снабжён комментариями по ключевым местам.

### mergeByCellValues: пример с серверными данными

Данные плоские, всё считает «сервер» (в примере его заменяет функция
`selectPage`), таблица только рисует полученную страницу.

Что здесь показано:

- поиск, фильтры, сортировка и пагинация в `manual`-режиме — считает потребитель;
- составные ключи пути (`divPath` / `unitPath` / `teamPath`) против ложного
  слияния одинаковых имён из разных веток;
- сортировка внутри команды — блоки не рассыпаются;
- закрепление колонок вместе с групповой шапкой;
- редактирование с возвратом правок страницы в полный набор.

### subRows: дерево с пагинацией

Данные — дерево, и оно остаётся у потребителя: таблице отдаётся страница целых
поддеревьев.

Что здесь показано:

- пагинация по верхним блокам (дивизионам) со своим списком «показывать по»;
- `manual`-поиск, сортировка и фильтры, посчитанные по дереву
  (функция `selectTreePage`);
- сортировка показателей внутри команды и перестановка веток по имени;
- возврат правок листьев обратно в дерево.

### rowsGrouping: группировка пользователем

Данные плоские и передаются целиком, остальное делает таблица. Самый короткий
код из трёх.

Что здесь показано:

- встроенные поиск, сортировка и фильтры — применяются до сборки групп;
- выбор состава группировки пользователем (кнопка `groupButton`);
- полный стейт фильтров: ключ на каждый фильтр из колонок;
- без пагинации — чтобы собрать группы, таблице нужны все строки сразу.

## Как перенести пример к себе

1. Замените данные и типы строк на свои. Сохраните стабильный `id` строки — на
   нём держатся выделение и возврат правок, между страницами он меняться не
   должен.
2. Замените `selectPage` / `selectTreePage` реальным запросом к серверу. Контракт
   тот же: параметры выборки на входе, страница и общее количество на выходе.
3. Проверьте, что в `filtering.state` есть ключ каждого фильтра из колонок (со
   значением «показать всё»), — селект-фильтр без своего ключа молча отсеет все
   строки.
4. Для `mergeByCellValues` заведите составные ключи пути, если одинаковые
   названия возможны в разных ветках иерархии.
5. Уберите фичи, которые вам не нужны, — настройки в примерах независимы друг от
   друга: пагинация, закрепление, чекбоксы, редактирование отключаются по
   отдельности.
