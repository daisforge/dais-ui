# StickyRowsCols API

## tableConfig.stickyColumns

```ts
stickyColumns?: readonly string[] | ((column: ColumnConfig<RowType>) => boolean);
```

Колонки, которые прилипают к левому краю при горизонтальной прокрутке. Два способа задать:

**Ключи** (`key` из `columnConfig`):

```tsx
tableConfig={{ stickyColumns: ['region', 'total'] }}
```

**Предикат** — когда липкость зависит от свойств колонки:

```tsx
tableConfig={{ stickyColumns: (column) => column.key.startsWith('total') }}
```

- Порядок ключей не важен, несуществующие ключи игнорируются.
- Служебные колонки (нумерация строк, чекбоксы) липкими не становятся — они и так закреплены.
- Липкие колонки встают правее закреплённых (`columnsControl.pinnedDefault`) и колонки нумерации.

## tableConfig.stickyRows

```ts
stickyRows?: readonly number[] | ((row: RowType, rowIndex: number) => boolean);
```

Строки, которые прилипают под шапкой. Два способа задать:

**Предикат** — вызывается для отображаемых строк данных, `true` — строка липкая.

```tsx
tableConfig={{ stickyRows: (row) => row.kind === 'subtotal' }}
```

- Работает с сортировкой и фильтрами: `rowIndex` — индекс среди отображаемых строк.
- Получает только строки данных (`RowType`): строки групп (`rowsGrouping`) и заглушки загрузки (скелетоны) в предикат не попадают и липкими не становятся.
- Результаты кешируются: строка, оставшаяся тем же объектом на том же месте, повторно не проверяется. При подгрузке чанками предикат вызывается только для новых строк, при редактировании — только для изменённых.
- Кеш привязан к функции: передавайте стабильный предикат (`useCallback` или константа вне компонента), иначе каждый рендер проверит все строки заново.

**Индексы** — передаются в таблицу как есть, без прохода по строкам.

```tsx
tableConfig={{ stickyRows: [0, 250000, 500000] }}
```

- Подходит для больших таблиц, где позиции липких строк известны заранее (например, их возвращает сервер).
- Индексы относятся к итоговому отображаемому списку, а не к исходному массиву `rows`. Сортировка, фильтры, группировка (`rowsGrouping` добавляет строки групп) и раскрытые узлы дерева (`subRows`) сдвигают нумерацию — индексы пересчитывает тот, кто их передаёт. Если позиции зависят от этих фич, удобнее предикат.
- Индексы за пределами таблицы игнорируются.

Итоговые строки (`bottomSummaryRows`) закреплены снизу всегда и липкими не становятся.

## Рекомендации

- Держите число липких строк небольшим: прилипшие строки занимают место под шапкой.
- Для отчётов удобно делать липкими итоги разделов — при прокрутке видно, к какому разделу относятся данные.
- Для миллионов строк передавайте индексы; для подгружаемых чанками данных — стабильный предикат.
