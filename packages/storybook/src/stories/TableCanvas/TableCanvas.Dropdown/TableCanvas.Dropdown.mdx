# Дропдаун

Выпадающий список пунктов, который открывается по левому клику или наведению на элемент внутри ячейки: кнопку «три точки», кнопку действий, иконку. Пункты такие же, как у контекстного меню таблицы, подгружать их можно асинхронно.

Чем отличается от соседних механизмов:

- Контекстное меню (раздел [ContextMenu](/docs/локальные-компоненты-tablecanvas-contextmenu--docs)) открывается правой кнопкой по ячейке или шапке целиком и настраивается в `tableConfig` на всю таблицу. Дропдаун открывается левой кнопкой или наведением на конкретный элемент и настраивается на этом элементе.
- Поповер (раздел [Popover](/docs/локальные-компоненты-tablecanvas-popover--docs)) показывает произвольную разметку. Дропдаун показывает список пунктов и сам обрабатывает выбор. Открытие, якорь и правила закрытия у них общие.

## Ключевые особенности

- Задаётся пропом `dropdown` на любом Canvas-элементе, без включателей в `tableConfig`.
- Открывается по левому клику или по наведению (`trigger`).
- Пункты те же, что у контекстного меню: разделители, вложенные пункты, своя отрисовка.
- Асинхронная подгрузка пунктов через `getItems` с промисом, состояния загрузки и ошибки.
- Общие настройки для всей таблицы в `tableConfig.dropdown`.

## Как подключить

Добавьте проп `dropdown` к Canvas-элементу в `renderCell`, `renderHeaderCell` или в `name` группы колонок. Ничего включать в `tableConfig` не нужно.

```tsx
renderCell: ({ row }) => (
  <Canvas.IconButton
    icon={<IconDotsVerticalCenteredOutline />}
    dropdown={{
      items: [
        { value: 'open', label: 'Открыть' },
        { value: 'copy', label: 'Копировать ссылку' },
        { value: 'delete', label: 'Удалить' },
      ],
      onItemSelect: (item) => handleAction(item.value, row),
    }}
  />
);
```

Курсор над таким элементом становится `pointer`.

Если на одном элементе заданы и `popover`, и `dropdown`, открывается поповер.

## Как это устроено

- На таблице открыт только один всплывающий слой. Новый дропдаун закрывает предыдущий, а также открытый поповер и поповер фильтра в шапке.
- Дропдаун привязан к якорю: невидимому DOM-элементу, который таблица ставит точно на место нарисованного элемента. От границ якоря считаются `placement` и `offset`. Якорь не перехватывает клики, они идут на канвас.
- Если клик по элементу попал в дочерний элемент, который остановил всплытие (`event.stopPropagation()`), дропдаун не открывается.

## Пункты

Пункты задаются одним из двух полей:

- `items`, готовый массив пунктов;
- `getItems`, функция, которая возвращает пункты сразу или промисом. Вызывается при каждом открытии.

Тип пункта тот же, что у контекстного меню: `value`, `label`, `disabled`, `contentLeft` и `contentRight`, разделители `dividerBefore` и `dividerAfter`, вложенные `items`. Своя отрисовка пункта задаётся через `renderItem`, содержимое над списком и под ним через `beforeList` и `afterList`.

`onItemSelect(item, { close })` вызывается при выборе пункта, в том числе пункта с вложенными пунктами. После выбора пункта без вложенных пунктов список закрывается (`closeOnSelect`, по умолчанию `true`).

Конфиг элемента, как и у поповера, вычисляется в момент открытия: `items` и колбэки берутся из того рендера ячейки, в котором дропдаун открыли. Для данных, которые должны быть свежими в момент открытия, используйте `getItems`.

## Асинхронная подгрузка пунктов

Если `getItems` вернул промис, список открывается сразу и показывает `loadingItems`, пока промис не разрешился. По умолчанию это один неактивный пункт «Загрузка...»; для скелетонов задайте свои пункты и `renderItem`.

```tsx
dropdown={{
  getItems: () => api.loadActions(row.id),
  loadingItems: SKELETON_ITEMS,
  renderItem: (item) =>
    String(item.value).startsWith('__skeleton') ? <SkeletonRow /> : item.label,
  renderError: ({ error, retry }) => (
    <ErrorBlock message={String(error)} onRetry={retry} />
  ),
}}
```

Если промис отклонился или `getItems` бросил исключение, вместо списка показывается `renderError({ error, retry, close })`. Без `renderError` показывается неактивный пункт «Не удалось загрузить». Ответ, пришедший после закрытия дропдауна, игнорируется.

Отличие от контекстного меню: там запросом владеет потребитель и перечитывает пункты из `tableConfig` на каждом рендере. Дропдаун элемента получает промис и состояние загрузки держит сам.

## Открытие по клику и по наведению

Поле `trigger` на элементе: `'click'` (по умолчанию) или `'hover'`.

Как ведёт себя дропдаун по наведению:

- открывается через `mouseEnterDelay` (по умолчанию 300 мс), если курсор всё ещё над элементом;
- держится, пока курсор над элементом или над списком, в том числе на пути между ними;
- закрывается через `mouseLeaveDelay` (по умолчанию 200 мс) после того, как курсор ушёл и с элемента, и со списка;
- клик мимо его не закрывает, он закроется, когда уйдёт курсор;
- не перебивает открытый дропдаун или поповер по клику и фильтр в шапке;
- если его закрыли, пока курсор остался на элементе (выбор пункта, Esc), заново он откроется только после того, как курсор уйдёт с элемента и вернётся.

## Закрытие

Дропдаун закрывается:

- выбором пункта без вложенных пунктов (`closeOnSelect`, по умолчанию `true`);
- кликом вне списка (`closeOnOutsideClick`, по умолчанию `true`), для дропдауна по клику;
- повторным кликом по тому же элементу, для дропдауна по клику;
- уходом курсора с элемента и списка, для дропдауна по наведению;
- по Esc (`closeOnEsc`, по умолчанию `true`);
- скроллом таблицы по любой оси (`closeOnScroll`, по умолчанию `true`): якорь нарисован на канвасе и за скроллом не едет;
- при ресайзе таблицы, переходе в полный экран, ресайзе или перестановке колонки;
- если на месте строки под дропдауном оказалась другая строка (сортировка, удаление, новые данные). Строки сравниваются по ключу из `rowKeyGetter` (`editing`, `selecting`, `subRows` или `mergeCells`), а без него по ссылке;
- когда таблица скрывается (смена вида, оверлей загрузки);
- вызовом `close` из `onItemSelect` или `renderError`.

`onOpen` и `onClose` вызываются ровно по одному разу на каждое открытие.

## Фокус и клавиатура

Открытие дропдауна не забирает фокус у таблицы: стрелки и редактор ячейки продолжают работать, пока список открыт. Esc из таблицы закрывает список и до таблицы не доходит. Пункты выбираются мышью; открыть дропдаун и ходить по пунктам с клавиатуры пока нельзя. Для экранных дикторов задайте подпись списка через `ariaLabel`.

## Настройки и значения по умолчанию

На элементе задаются: `trigger`, `items` или `getItems`, `onItemSelect`, `placement`, `offset`, `listWidth`, `listMaxHeight`, `variant`, `size`, `zIndex`, `closeOnSelect`, `closeOnScroll`, `closeOnOutsideClick`, `closeOnEsc`, `mouseEnterDelay`, `mouseLeaveDelay`, `loadingItems`, `renderError`, `renderItem`, `beforeList`, `afterList`, `ariaLabel`, `onOpen`, `onClose`.

Чтобы не повторять одни и те же настройки на каждом элементе, их можно задать один раз для всей таблицы в `tableConfig.dropdown`. Это только значения по умолчанию: значение на элементе важнее. Там доступны `placement`, `offset`, `listWidth`, `listMaxHeight`, `variant`, `size`, `zIndex`, `closeOnSelect`, `closeOnScroll`, `closeOnOutsideClick`, `closeOnEsc`, `mouseEnterDelay`, `mouseLeaveDelay`, `loadingItems`, `renderError`. `trigger` задаётся только на элементе.

```tsx
tableConfig={{
  dropdown: {
    placement: 'right',
    listWidth: 200,
    variant: 'tight',
  },
}}
```

`listWidth` и `size` по умолчанию зависят от размера строк таблицы, как у контекстного меню. Остальные встроенные значения: `trigger: 'click'`, `placement: 'bottom'`, `offset: [0, 4]`, `variant: 'normal'`, `closeOnSelect: true`, `closeOnScroll: true`, `closeOnOutsideClick: true`, `closeOnEsc: true`, `mouseEnterDelay: 300`, `mouseLeaveDelay: 200`.

Подробное описание типов в разделе [API](/docs/локальные-компоненты-tablecanvas-dropdown-api--docs).
