# CellsSelection

Выделение в таблице задаётся пропом **`tableConfig.cellsSelection.mode`** — это
фактическое нативное выделение ячеек. По нему работают copy/paste, рамка
выделения, fill-handle и затемнение шапки/нумерации.

> Это **отдельная ось** от `highlightActiveType` (визуальная подсветка строки) и
> от `selecting` (выбор строк чекбоксами).

## Ключевые особенности

- Четыре режима выделения ячеек: одна ячейка, диапазон, несколько диапазонов, выключено
- Три независимые оси: ячейки, колонки (по шапке), строки (по нумерации)
- Copy/paste по любому выделению, включая мультивыбор со схлопыванием промежутков
- Controlled-режим через `state`-кортеж
- Автосброс выделения при смене данных (сортировка, фильтр, страница) — см. раздел ниже

## Значения cellsSelection.mode

- `'range-cell'` — выделение диапазона ячеек (по умолчанию). Тянем мышкой.
- `'multi-range-cell'` — как `range-cell`, но **Ctrl/Cmd** докидывает несколько
  диапазонов (см. ниже).
- `'cell'` — выделение одной ячейки.
- `'disabled'` — выделение ячеек отключено.

## Мультивыбор диапазонов (multi-range-cell)

При `cellsSelection: { mode: 'multi-range-cell' }` можно выделить несколько прямоугольных
диапазонов: тянем мышкой первый, затем **Ctrl/Cmd + клик/драг** докидываем
остальные. Заливка и рамка — у всех выделенных.

**Copy (Ctrl+C)** работает для разрозненного выбора, если все ячейки лежат:

- в пределах **одной колонки** — значения копируются подряд, пустые промежутки
  между ними схлопываются;
- либо в пределах **одной строки** — аналогично по горизонтали;
- либо куски складываются в **сплошной прямоугольник** без дыр — тогда он
  копируется как обычный диапазон.

Разброс сразу **по строкам и колонкам** (2D) не переносится — copy/paste для него
не срабатывают. Об этом таблица сообщает через модуль
[Notifications](?path=/docs/локальные-компоненты-tablecanvas-notifications--docs)
(`copy` / `paste`, code `multi-range-scattered`). Сама таблица тост не рисует:
подключите `notifications.onNotification` и покажите ошибку пользователю — иначе
отказ копирования выглядит как молчаливая поломка.

**Paste (Ctrl+V)** зеркально: вставка идёт в выбранные ячейки подряд, схлопывая
промежутки. Полный интерактивный пример copy/paste — в разделе
**Copy-Paste-Fill**.

## Оси выделения

Выделение работает по трём независимым осям. Любая из них поддерживает
copy/paste (**Ctrl+C / Ctrl+V**) по текущему выделению.

- **Ячейки / диапазон** — мышью по области данных, зависит от `cellsSelection.mode`.
- **Колонки** — клик по шапке колонки.
- **Строки** — клик/драг по колонке нумерации (`rowMarkers`).

### Выделение колонок

Клик по шапке выделяет колонку целиком:

- **Клик** — одна колонка.
- **Shift + клик** — смежный диапазон колонок (рисуется нативно, с fill-handle).
- **Ctrl/Cmd + клик** — несмежный выбор: добавить/убрать колонку.

Клик по иконкам сортировки/фильтрации в шапке выделение **не** вызывает.
Управляется флагом `cellsSelection.enableColumnSelection` (по умолчанию `true`).

### Выделение строк

Клик/драг по колонке нумерации выделяет строку(и):

- **Клик / драг** — смежный диапазон строк (рисуется нативно, с fill-handle).
- **Ctrl/Cmd + клик** — несмежный выбор отдельных строк.

Требует включённой колонки нумерации (`rowMarkers`). Управляется флагом
`cellsSelection.enableRowSelection` (по умолчанию `true`).

## Включение / выключение осей

Выделение колонок и строк можно выключать независимо через `tableConfig.cellsSelection`:

```ts
<TableCanvas
  tableConfig={{
    rowMarkers: { startIndex: 1 },
    cellsSelection: {
      enableColumnSelection: false, // клик по шапке не выделяет колонку
      enableRowSelection: false, // клик по нумерации не выделяет строку
    },
  }}
/>;
```

Оба флага по умолчанию `true`. Выделение ячеек/диапазона при этом продолжает
работать — оно управляется отдельным `cellsSelection.mode`.

## Controlled-режим

Выделением можно управлять снаружи через `state`-кортеж:

```ts
const gridSelectionState = useState<GridSelection>(EMPTY_SELECTION);

<TableCanvas
  tableConfig={{
    cellsSelection: { mode: 'range-cell', state: gridSelectionState }, // [value, setter]
  }}
/>;
```

Сброс: `setter({ current: undefined, rows: CompactSelection.empty(), columns: CompactSelection.empty() })`.
Контролируется нативное выделение (ячейки/диапазон/смежные строки и колонки);
несмежный Ctrl-выбор колонок/строк — внутренний (own-state), снаружи не задаётся.

`CompactSelection` и тип `GridSelection` реэкспортируются из
`@daisforge/ui/components/TableCanvas`.

## Сброс выделения при смене данных

Рамка выделения привязана к позициям ячеек. Если состав или порядок строк
изменился, старая рамка указывала бы на чужие данные — поэтому таблица сбрасывает
её сама. Правило простое: **сбрасываем, когда меняются данные под рамкой; не
сбрасываем, когда меняется только вид**.

Рамка сбрасывается:

- сортировка, фильтр, поиск, группировка — в том числе в manual-режимах
  (критерий поменялся, ответа бэка ждать не нужно);
- пришёл новый массив `rows` (смена страницы, рефетч с другим составом).

Рамка живёт:

- скролл, уход фокуса, клики по тулбару;
- скрытие, перестановка, закрепление и ресайз колонок (записи под рамкой те же);
- live-обновление с тем же составом строк — если передан `dataRevision` (см. ниже).

Три состояния независимы: **рамка** сбрасывается первой; **активная ячейка** при
возможности переезжает на свою запись; **чекбоксы строк** (`selecting`) живут по
ключам и переживают всё.

### dataRevision — «те же строки или другие?»

Сортировку и фильтр таблица видит сама, а вот пагинацию и рефетч делает
потребитель — таблица получает просто новый массив. По умолчанию любой новый
массив `rows` считается новыми данными (сброс). Если у вас live-обновление и
состав не менялся, передайте `dataRevision` — тогда сброс происходит только по
его смене:

```ts
<TableCanvas
  rows={pageRows}
  tableConfig={{
    cellsSelection: { dataRevision: `${page}:${pageSize}` },
  }}
/>;
```

Значение может быть любым — таблица его не читает, только сравнивает с прошлым.

### Восстановление активной ячейки

Передайте `cellsSelection.rowKeyGetter` (или он возьмётся из
`selecting`/`subRows`/`mergeCells`) — тогда после сортировки или фильтра активная
ячейка останется на своей записи, и таблица к ней доскроллит. Если строка исчезла
из проекции (отфильтрована, другая страница) — выделение просто сбрасывается.

### Esc — в два шага

Первое нажатие сводит диапазон к одной активной ячейке, второе снимает и её.
Так же ведёт себя клик вне таблицы.

Живой пример — стори «Сброс при смене данных (демо)» и «Диагностика: колонки при
активном выделении».
