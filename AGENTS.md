# @daisforge/ui — инструкции для агентов

Единый источник правил для Claude Code, Codex и других агентов. `CLAUDE.md`
подключает этот файл. Пиши по-русски: код-ревью, комментарии, описания тестов,
коммиты.

`@daisforge/ui` — библиотека React-компонентов на базе `@salutejs/sdds-finai`
(Plasma). Её используют десятки приложений, которые мы не видим. Поэтому главное
требование к любому изменению — **не сломать потребителей**: API, поведение,
вёрстку.

## Перед тем как писать код

1. **Найди существующее.** Компонент, утилиту или хук — через MCP-сервер
   `daisforge-ui` (`search_components`, `get_component`) или поиском в
   `packages/ui-kit/src`. Не создавай второй `debounce`, второй `Flow`, вторую
   обёртку над тем же атомом sdds-finai.
2. **Посмотри соседей.** Новый код повторяет структуру, имена и стиль ближайшего
   похожего компонента, а не общие привычки.
3. **Держи diff минимальным.** Не переформатируй, не переименовывай и не
   «улучшай» код вне задачи. Попутные находки — в отчёт, не в diff.
4. Для изменения компонента читай скилл
   [component-change](.agents/skills/component-change/SKILL.md).

## Публичное API — контракт

Публичное API — всё, что достижимо из `packages/ui-kit/src/index.ts`:

- имена экспортов (компоненты, хуки, утилиты, типы, константы, токены);
- пропсы и их типы, значения по умолчанию, сигнатуры колбэков;
- compound-части (`ModalDF.Header`) и CSS-классы из `classNames.ts`, которые
  экспортируются как `<name>ClassNames` — потребители стилизуют по ним;
- поведение: когда вызывается колбэк, что он получает, что рендерится по
  умолчанию;
- реэкспорты из `@salutejs/sdds-finai`: обновление sdds-finai меняет и наш API.

Правила:

- **Не удаляй и не переименовывай** экспорт или проп. Нужна замена — добавь
  новый, старый пометь `/** @deprecated Используйте <новый> */` и оставь
  работающим.
- **Новые пропсы — опциональные**, а без них поведение остаётся прежним.
- **Не сужай типы** (убрать вариант из union, сделать проп обязательным, сменить
  тип аргумента колбэка) и не меняй значения по умолчанию.
- **Имена — как у соседей и sdds-finai**: `opened`/`onClose` (ModalDF,
  DrawerDF), `view`, `size`, `disabled`. Не вводи синонимы (`isOpen` рядом с
  `opened`), не смешивай `onChange(value)` и `onChange(event)` в одном
  семействе. У form-компонентов `onChange` возвращает значение, а не event.
- Ломающее изменение — только по процессу ниже.
- Любое изменение публичного API перечисли в отчёте и в описании PR отдельным
  пунктом.

### Ломающие изменения: сначала deprecated, удаление в major

Сначала ищи совместимый путь: новый проп рядом со старым, приём старого
значения с преобразованием в новое, новый компонент рядом со старым.

Процесс ниже касается только API, которое уже вышло в опубликованной версии.
Добавленное после последнего релиза (есть в `develop`, нет в npm) можно
переименовать или убрать без `@deprecated` — потребители его ещё не получили.
Проверить, опубликовано ли имя:
`git grep -n "<Имя>" "$(git describe --tags --match 'v*' --abbrev=0)" -- packages/ui-kit/src`.

Если опубликованное API нужно заменить — всегда в два этапа:

1. **Minor: пометить устаревшим.** Добавь новый вариант, старый оставь
   работающим (лучше через преобразование в новый) и пометь:

   ```ts
   /** @deprecated Используйте `options`. Будет удалён в следующей major-версии. */
   items?: DropdownItem[];
   ```

   Коммит обычный (`feat`), без `BREAKING CHANGE`. В описании PR — что
   устарело и на что заменить; в MDX — пометка у устаревшего пропа.

2. **Major: удалить.** `@deprecated` живёт до следующей major-версии и
   удаляется только в ней. Удалять можно лишь то, что было помечено устаревшим
   хотя бы в одном опубликованном релизе. Сроки major-релиза решает команда:
   ломающие изменения собираются пачкой, по одному их не выпускают. Агент не
   удаляет `@deprecated` по своей инициативе. Коммит удаления — с телом:

   ```
   feat(Dropdown): удалён устаревший проп items

   BREAKING CHANGE: проп items удалён, используйте options — формат тот же
   ```

   Текст после `BREAKING CHANGE:` попадает в CHANGELOG — пиши его как
   инструкцию по миграции. В описании PR — раздел «Миграция» с кодом
   «было → стало». Список кандидатов на удаление —
   `rg "@deprecated" packages/ui-kit/src`.

Изменения, которые нельзя пометить `@deprecated`, тоже ждут major:

- **Смена поведения или значения по умолчанию.** В minor новое поведение
  включается опцией (по умолчанию — старое), в major меняется значение по
  умолчанию.
- **Обновление `@salutejs/sdds-finai` и других зависимостей**, после которого
  меняются реэкспортируемые типы или поведение. Сохрани наш API адаптером;
  если нельзя — обновление уходит в major с `BREAKING CHANGE`.

Squash-merge через GitHub заменяет тело коммита описанием PR — в этом случае
строку `BREAKING CHANGE:` нужно сохранить в итоговом сообщении.

## Как устроен компонент

Компоненты лежат в `packages/ui-kit/src/components/<Name>/` (layouts — в
`layouts/`, интеграции с react-hook-form — в `formComponents/`).

- **Обёртка над атомом sdds-finai** — только `index.ts` с реэкспортом (см.
  `Badge`, `Button`).
- **Собственный компонент** (см. `ModalDF`, `DrawerDF`):
  - `<Name>.tsx` — компонент, `forwardRef`, compound-части через
    `Object.assign(Comp, { Header, Footer })`;
  - `types.ts` — публичные типы пропсов (`<Name>Props`);
  - `styled.ts` — styled-components;
  - `classNames.ts` — `export const cls = { root: '<name>_root', ... } as const`;
  - `constants.ts`, `components/`, `hooks/`, `utils/` — по необходимости;
  - `index.ts` — явные именованные экспорты; в новом коде без `export *`,
    чтобы наружу не утекали внутренние имена.
- Новый компонент экспортируется из `packages/ui-kit/src/index.ts`
  (`export * from './components/<Name>'`, по алфавиту) и регистрируется в
  `generators/meta-info/config/meta-config.json` (`type`: `wrapper`,
  `composition`, `standalone` или `form`).

## Код

- **TypeScript:** без `any` (используй `unknown`, дженерики, типы sdds-finai),
  без `@ts-ignore`; `as`-приведения и `eslint-disable` — только с комментарием,
  почему иначе нельзя.
- **Стили:** styled-components и токены. Цвета и типографика — из
  `@ui-kit/tokens`, отступы `s.x8`, радиусы `br.m`, брейкпоинты `breakP` — из
  `@ui-kit/constants`. Никаких литералов цветов и инлайн-стилей в коде
  библиотеки (в stories допустимо). Служебные пропсы styled-компонентов — с
  префиксом `$` (`$fullScreened`), чтобы не попадали в DOM.
- **Импорты:** алиасы `@ui-kit/...`, без циклических зависимостей (проверка —
  `npm run ui-kit:circular-check`).
- **Готовые утилиты** (`packages/ui-kit/src/utils/`): `mergeRefs`, `bubble`,
  `eventBus`, `clickStream`, `debounce`, `throttle`, `getTokenValue`,
  `getValue`, `contextStoreWithSelectors`, хуки в `utils/hooks/`. Описание — в
  [README](README.md#-паттерны-и-соглашения).
- **Доступность:** интерактивные элементы — нативные (`button`, `a`) или с
  ролью, `aria-*` и управлением с клавиатуры; у иконок-кнопок есть
  `aria-label`.
- **Таблицы:** новое — только на `TableCanvas` (Glide Data Grid). `Table`
  (react-data-grid) — устаревшая, только поддержка.
- Комментарии объясняют «почему», а не «что».

## Проверки

Pre-commit прогоняет `eslint --fix` по застейдженным TS-файлам. Хук агента
(`scripts/agent-hooks/check-changed.mjs`; Claude — `.claude/settings.json`,
Codex — `.codex/hooks.json`, работает после доверия проекту в `/hooks`)
запоминает состояние в начале хода, а в конце проверяет только изменённое за
ход, включая удалённые файлы и сделанные коммиты: ESLint по файлам, `tsc` по
затронутым пакетам (для ui-kit — ещё его тесты и Storybook). Блокируют только
новые ошибки: то, что было сломано до хода, хук не засчитывает агенту. Файлы
он не исправляет. Если хук вернул ошибки — исправь причину. Хуки не заменяют
осознанную проверку.

| Что изменилось        | Команда                                             |
| --------------------- | --------------------------------------------------- |
| код ui-kit            | `npx nx run ui-kit:typecheck`, `npx eslint <файлы>` |
| логика компонента     | `npx nx test ui-kit -- <Name>` (юнит-тесты Vitest)  |
| stories, MDX          | `npx nx run storybook:typecheck`                    |
| вид компонента        | `npm run screenshot:test -- <Name>` (Docker)        |
| экспорты, зависимости | `npm run build`, `npm run ui-kit:circular-check`    |
| meta-config, MDX, MCP | `npm run mcp:check`                                 |
| Markdown              | `npm run format:md`                                 |

Упавшую или не запущенную проверку называй прямо. Не выдавай частичный прогон
за полный.

## Когда задача готова

- [ ] Публичное API не сломано, либо изменение согласовано и описано.
- [ ] Новое поведение покрыто юнит-тестом или `play`-сценарием, исправленный
      баг — тестом, который падал до исправления. Правила — скилл
      [write-tests](.agents/skills/write-tests/SKILL.md).
- [ ] Видимое изменение есть в stories, MDX обновлён по
      [гайду документации](generators/meta-info/GUIDE.md).
- [ ] Скриншоты: изменённые PNG просмотрены и намеренны
      ([инструкция](packages/storybook/test/screenshot-tests.md)).
- [ ] Проверки из таблицы выше прошли.
- [ ] Отчёт: что сделано, что изменилось в API, что проверено и чем, что не
      проверено.

## Чего не делать

- Не правь сгенерированное: `dist/`, `_docs/meta/`,
  `packages/storybook/src/*.string.json`, `CHANGELOG.md`, токены из
  `ui-kit:generate-tokens`.
- Не обновляй и не добавляй зависимости без просьбы.
- Не повышай допуски скриншотов и не добавляй skip ради зелёного прогона.
- Не ослабляй правила ESLint, `tsconfig` и проверки CI, чтобы прошёл код.
- Не публикуй (`npm publish`, `lerna version/publish`) и не пушь в `main` и
  `develop`.

## Git и PR

- Ветки от `develop`: `feature/<имя>`, `bugfix/<имя>`. PR — в `develop`.
- Коммит: `<тип>(<контекст>): <описание>`, типы и стиль — скилл
  [commit-message](.agents/skills/commit-message/SKILL.md). Хук
  `commit-msg` отклоняет неверный формат.
- Если изменения видны в Storybook, добавь в описание PR ссылки на превью:
  `https://daisforge.github.io/dais-ui/pr-preview/pr-<N>/?path=/story/<story-id>`
  (для `play` — с `&addonPanel=storybook/interactions/panel`). Превью
  публикуется после создания PR, поэтому ссылки добавляются вторым шагом через
  `gh pr edit <N> --body-file <файл>`.

## Скиллы

Источник — [.agents/skills](.agents/skills) (их читает Codex). Claude Code
читает только `.claude/skills`, там лежат копии: правь `.agents/skills`, затем
`npm run skills:sync`. Расхождение ловят pre-commit и CI (`skills:check`).

| Скилл              | Когда                                         |
| ------------------ | --------------------------------------------- |
| `component-change` | создать или изменить компонент, хук, утилиту  |
| `write-tests`      | юнит-тесты, `play`, скриншоты и PNG-эталоны   |
| `code-review`      | ревью своего diff перед отчётом или чужого PR |
| `generate-docs`    | MDX, JSDoc, описание компонента в Storybook   |
| `security-audit`   | проверка безопасности кода, CI, зависимостей  |
| `commit-message`   | сообщение коммита                             |
