# Генератор цветов таблицы: как это работает

Это генератор палитры для TableCanvas/TableGlide. Он превращает небольшой
набор семантических токенов дизайн-системы в полную палитру цветов таблицы —
все состояния всех поверхностей по всем шести темам. Генератор — инструмент
разработчика: запускается руками, в сборку библиотеки и в CI не входит.
Его результат — обычный закоммиченный файл
`packages/ui-kit/src/components/TableGlide/theming/table-colors.generated.ts`,
и только его видит остальной код.

Автор модели и формул — дизайн-система (Вероника Малышева, сборка от
18.09.2026); расчётный код в `code/` — её, слой интеграции
(`emit-table-colors.ts`) — наш.

## Зачем это нужно

Раньше цвета таблицы были захардкожены руками: отдельный hex на каждую тему,
тёмная тема при этом была копией светлой, а состояний (hover, выделение) для
большинства цветов не существовало вовсе. Модель генератора меняет подход:
**каждый цвет таблицы — это семантический токен темы в одном из четырёх
состояний**: `rest` (покой), `hover` (под курсором), `active` (в выделении),
`hoverActive` (под курсором внутри выделения). Руками не задаётся ни один
hex: меняется тема → меняются входные токены → все состояния пересчитываются.

Второй принцип: **всё тяжёлое считается заранее**. Вся математика цвета
(OKLCH) выполняется на этапе генерации, в палитру попадают готовые
непрозрачные hex. Canvas-рендер в рантайме ничего не вычисляет и ничего не
накладывает — наложение выделения на цвет ячейки уже «запечено» в hex.
Поэтому модель ничего не стоит на больших данных: хоть миллион строк.

## Вход

Входных цветов всего ~18 — это семантические токены темы (`surface-solid-card`
— фон ячейки, `surface-accent-minor` — шапка и отмеченные строки,
`surface-transparent-accent` — полупрозрачная заливка выделения, статусные
`surface-*-minor`, токены редактирования `data-yellow-light` /
`data-blue-light` и т.д.). Для каждого выписан hex по шести темам: `light`,
`dark`, `betaCoreLight`, `betaCoreDark`, `highContrastLight`,
`highContrastDark`. Источник значений — CSS тем атомарной команды
(`@salutejs/sdds-themes` 0.79.1, beta core 0.1.0); `highContrastDark` как
темы не существует — это договорённая копия dark. Всё это лежит в
`code/table-token-sources.ts` (объект `SEMANTIC`), там же — настройки тем
(`THEME_SETTINGS`: светлая или тёмная, множитель шага) и карта ключей
(о ней ниже).

## Формула состояний

Расчёт идёт в цветовом пространстве OKLCH — оно перцептивно равномерное:
одинаковое числовое изменение выглядит одинаково заметным на любом цвете.

**hover — «шаг по лучу».** Берётся опорная точка: белый в светлых темах,
чёрный в тёмных. Через опору и цвет токена проводится луч, и цвет сдвигается
вдоль него на фиксированную ступень δ = 0.025 (в тёмных темах ×1.2 —
на тёмном фоне изменения заметны хуже). Движение вдоль луча означает:
светлота уходит от опоры, насыщенность растёт пропорционально удалению,
тон не меняется. Ключевое свойство: перцептивное расстояние между цветом и
его hover-вариантом равно ровно 100·δ **для любого входного цвета** —
поэтому hover одинаково заметен и на белой ячейке, и на жёлтой, и в тёмной
теме. У белого фона нет насыщенности и луч не определён — направление для
него берётся у серого `surface-solid-primary` той же темы (поэтому белые
ячейки темнеют «в серый», а цветные — «в свой цвет»; то самое различие
hover-а обычных и цветных ячеек). Если при шаге насыщенность выходит за
границы sRGB (бывает только у очень ярких цветов), она уменьшается при тех
же светлоте и тоне.

**active — наложение выделения.** Это не шаг, а честный альфа-композит:
полупрозрачный `surface-transparent-accent` темы (альфа 12% в светлых темах,
20% в тёмных) накладывается на цвет покоя по каналам sRGB — ровно так, как
рисует выделение компонент Selection Area в макетах. Результат «сплющен» в
непрозрачный hex. Так жёлтая редактируемая ячейка в выделении становится
приглушённо-жёлто-голубой, а не исчезает под синим слоем.

**hoverActive** — ещё один шаг по лучу, но уже от цвета выделения: hover
показывается и на выделенных ячейках, усиливая их.

Не всё считается формулой. Токены делятся на группы по префиксу имени:
заливки (`surface-*`, `data-*`) идут через формулу; текст и обводки
(`text-*`, `outline-*`) пока берутся из темы как есть (правило для «чернил»
дизайн-система выдаст отдельно); `background-*` — статичные цвета без
состояний (затухание при скролле).

## Карта ключей и выход

`TABLE_COLORS` в `table-token-sources.ts` — карта из ~53 записей вида
«ключ в коде таблицы → токен × состояние»: например,
`bgHeaderHovered = surface-accent-minor × hover`,
`bgEditableCellActive = data-yellow-light × active`. Имена ключей совпадают
с тем, что таблица использовала исторически, плюс новые ключи для состояний,
которых раньше не было (статусные ячейки, hoverActive-семейство).

Функция `buildTableColors()` прогоняет карту через формулу и отдаёт палитру:
`{ ключ: { light: '#…', dark: '#…', … } }`. Если в какой-то теме нет
входного токена, значение честно равно `null` — это «в теме нет данных»,
а не ошибка расчёта.

Наш скрипт `emit-table-colors.ts` берёт эту палитру и доводит до прода:
закрывает `null`-дыры временными значениями, согласованными с дизайнером
(например, beta-темам не хватает `data-yellow-light` — подставляются
согласованные Amber/100 и Amber/950; важно: их четыре состояния считаются
той же формулой `fillStates`, а не подбираются руками), валидирует, что не
осталось ни одного пустого значения (иначе падает), и пишет
`table-colors.generated.ts`: 53 ключа × 6 тем, каждый подставленный
временный hex помечен комментарием-причиной. Туда же пишется
`TABLE_FILL_PARAMS` — параметры формулы по темам для рантайма (см. ниже).

## Рантайм: единственное место, где формула живёт в браузере

Потребитель таблицы может красить ячейки произвольным цветом
(`themeOverride → bgCell`). Для таких цветов палитру заранее не посчитать,
поэтому в ui-kit живёт контролируемая копия fill-части формулы —
`packages/ui-kit/src/components/TableGlide/theming/fill-states.ts` — с кэшем
по паре «тема + hex». Стоимость — O(числа уникальных цветов), не O(ячеек):
у потребителя обычно 3–7 статусных цветов, значит формула выполнится 3–7 раз
за всю жизнь таблицы. Эквивалентность копии и генератора закреплена тестом
(`fill-states.test.ts` сверяет результаты с палитрой бит-в-бит).

Как палитра применяется в отрисовке — кратко: фон ячейки получает
rest/hover-hex, а в per-cell тему кладётся `accentLight` = active/hoverActive;
заливка выделения Glide берёт `accentLight` из per-cell темы и применяется
ровно тогда, когда ячейка в выделении. Функция смешивания цветов в форке
(`blend`) для непрозрачного hex возвращает его как есть — то есть рантайм
просто подставляет готовые цвета, ничего не вычисляя.

## Файлы

Код дизайн-системы (источник истины, по смыслу не правим):

- `code/table-token-states.ts` — формулы: конвертация hex ↔ OKLCH (матрицы
  Ottosson), наложение альфы, шаг по лучу (`stepHex`), четыре состояния
  заливки (`fillStates`), обвязка по темам (`deriveStates`) и по карте
  ключей (`buildTableColors`). Без зависимостей.
- `code/table-token-sources.ts` — данные: `THEME_SETTINGS`, `SEMANTIC`,
  `CELL` (ссылки на фон/луч/выделение), `TABLE_COLORS`.
- `code/table-token-states.test.ts` — 17 тестов-спецификаций: неизменённые
  ключи совпадают со спекой 15.09; двенадцать пар «подложка + выделение» из
  макета воспроизводятся с точностью до единицы канала; шаг hover ровно δ;
  у каждого ключа шесть тем; `null` только там, где в теме нет данных;
  `fillStates(hex токена)` эквивалентен состояниям токена; насыщенные цвета
  не выходят за sRGB.
- `code/table-state-colors.ts` — замороженный снапшот спеки 15.09, нужен
  только регрессионному тесту.
- `code/generate.ts` — CLI дизайнера: пишет `output.json`, markdown и два
  CSV (содержимое `docs/`). `output.json` — её эталонный результат для
  сверки; палитру мы считаем сами тем же кодом через emit.
- `demo/table-states-prototype.html` — интерактивный прототип: живая таблица
  со всеми состояниями в каждой теме, матрица значений, экспорт. Открывается
  локально. Розовая штриховка в нём означает «в теме нет данных».

Наш слой:

- `emit-table-colors.ts` — выпуск палитры (описан выше);
- `INTEGRATION-STATUS.md` — статус интеграции и открытые вопросы к дизайнеру;
- `BACKLOG.md` — отдельные задачи, сознательно не вошедшие в ветку палитры;
- `tsconfig.json` — локальный, со смягчёнными флагами: строгие флаги
  репозитория (`noUncheckedIndexedAccess` и др.) ломают код дизайнера, а
  подгонять его нельзя — файлы заменяются 1-в-1 при обновлениях. По той же
  причине `code/` и `demo/` исключены из eslint (корневой `.eslintignore`).

Своей инфраструктуры зависимостей у папки нет: tsx/vitest/typescript/prettier
живут в devDependencies корня, скрипты — в корневом package.json.

## Команды (из корня репозитория)

```bash
npm run table-colors:palette        # палитра заливок → theming/table-colors.generated.ts
npm run table-colors:ink            # цвета «чернил» → TableGlide/ink-tokens.generated.ts
npm run table-colors:test           # тесты дизайнера (19) — после любой замены code/
npm run table-colors:typecheck      # tsc -p tsconfig.json папки
npm run table-colors:designer-docs  # пересчёт output.json/docs/csv дизайнера
npm run table-colors:format         # prettier: эта папка + ../table-ink-tokens (есть и :format-check)
```

После `table-colors:palette` обязательно прогнать `npx nx test ui-kit` —
тест эквивалентности рантайм-копии формулы должен остаться зелёным.

## Процедура обновления от дизайн-системы

1. Заменить файлы `code/` (и при необходимости `docs/`, `demo/`) целиком.
2. `npm run table-colors:format && npm run table-colors:test && npm run table-colors:typecheck`
   (форматирование prettier допустимо — семантика защищена тестами).
3. Пересмотреть временные значения в `emit-table-colors.ts`: возможно, дыры
   тем уже закрыты настоящими токенами и подстановки пора удалить.
4. `npm run table-colors:palette`, затем `npx nx test ui-kit`.
5. Глазами по стенду: Storybook → Локальные компоненты → TableCanvas →
   ColoringStates (все режимы выделения, hover, ошибки, 6 тем).

## Связанное

- Цвета «чернил» (текст, бейджи, кнопки внутри ячеек) собирает отдельный
  генератор `generators/table-ink-tokens/` — читает темы атомарной команды
  из node_modules. Запускается сам в конце `npm run update` / `updateX`.
  Какие цвета нужны и где их искать — его `lib/token-map.js`; в `report.md` —
  что поменялось у атомарки с прошлого запуска (новые и пропавшие
  переменные) и какие цвета взяты не напрямую из своей темы.
- Рантайм-копия fill-формулы:
  `packages/ui-kit/src/components/TableGlide/theming/fill-states.ts` —
  менять только синхронно с `code/table-token-states.ts`, защищено тестом.
- Текущие нерешённые вопросы — `INTEGRATION-STATUS.md`; задачи после
  ветки — `BACKLOG.md`.
