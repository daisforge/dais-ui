# Часть 1. Что сделано и что открыто

## Что работает

Интегрирована палитра **v1.2 целиком** (60 ключей, включая hover2). Все
цвета таблицы берутся из модели «семантический токен × состояние» по всем
шести темам, включая настоящую тёмную:

- **покой / hover / выделение / hover внутри выделения** для обычных ячеек;
- **ячейки со своим цветом** (жёлтые редактируемые, статусные
  positive/negative/warning/info, произвольные цвета потребителя) во всех
  состояниях, включая hover2;
- все способы выделения: диапазон мышью, колонка кликом по шапке
  (включая Ctrl-мультивыбор), строка кликом по нумерации;
- отмеченные чекбоксом строки и их пересечения с выделением и hover;
- **выбранная строка** (`highlightActiveType='row'`) — по правилу v1.2,
  см. ниже;
- **выделенная шапка под курсором** — на ступень глубже
  (`bgHeaderSelectedHovered`), листовая и групповая;
- красная рамка ошибки поверх любого выделения;
- подсветка строки под курсором (`hoverEffects.row`) включена по умолчанию;
- шесть тем; временные значения для недостающих токенов подставлены и
  помечены.

Стенд для проверки: Storybook → Локальные компоненты → TableCanvas →
ColoringStates (переключатели всех режимов, темы — глобальным тулбаром).
Там же — скриншот-тесты состояний по темам.

## Решения дизайнера v1.2 (05–07.10), которые применены

**Выбранная строка** — ровно по правилу из README дизайнера («Как
подключить», п. 3), сверено пиксельно со значениями палитры (light):

- обычная ячейка = `surface-accent-minor` × rest (#ECF6FC), под курсором
  × hover (#DEF0FA); нажатый чекбокс добавляет ступень (под курсором
  × hover2 #D0EAF8);
- наличие ненажатого чекбокса на цвет не влияет — старое правило
  «есть чекбокс → темнее» убрано;
- цветные ячейки — свой hover, под курсором свой hover2, **без наложения
  выделения**;
- пересечение с реальным выделением = выделение; служебная зона строки
  затемняется как при выделении;
- активная (кликнутая) ячейка — фон своей строки + рамка, без тонирования.

**Выделенная шапка под курсором** — пары из п. 6 подключены
(лист `bgHeaderHovered = bgHeaderSelectedHovered`, группа — то же).

**Имена цветов данных и текста:** `dataViolet` → `data-orchid` (значения
по каждой теме), `textTertiaryBase`/`textTertiaryVariant` → `text-tertiary`.
Ключ `disabled` (`#DDDDDD`) удалён: disabled — не цвет, а правило
«непрозрачность 40 %»; в коде он не использовался. `dataTeal` оставлен
временным значением arctic-300 `#14CC98` до появления `data-arctic-minor`
в теме.

**Объединённые ячейки** — поведение не меняли (hover по главной строке
блока, выделение полосами по пересечению); ждём отдельного решения.

## Открытые вопросы

1. **Временные токены** — запросы владельцам темы:
   `data-yellow-light` в light (нужен amber-100 вместо amber-150), в beta
   нет `data-yellow-light`/`data-blue-light`; в high contrast light нет
   `surface-solid-primary` (нет hover у серых цветов потребителя),
   `background-primary` и минорных статусных токенов.
2. **Контрастная тема**: множитель шага состояний подобрать на стенде.
3. **Правило «чернил»** (состояния текста и обводок) — когда появится,
   встанет в `deriveThemeStates` (ветка `usage !== 'fill'`), остальное не
   меняется. Отдельно без решения `onDarkTextPrimary96/56/28` — почти белый
   текст с непрозрачностью 96/56/28 %; оттенок `#F7F9FB` не совпадает с
   `--on-dark-text-primary` (`#F2F5F8`); в коде таблицы не используются —
   подтвердить замену или убрать (список —
   `generators/table-content-tokens/report.md`).
4. **Сохранённая ячейка** (`editedSuccessfullyCell*`) — ключи в палитре
   есть, canvas-состояния пока нет (красится CSS-слоем). Отдельная задача.
5. **Disabled-состояния canvas-контролов** (кнопки, чекбокс внутри ячеек):
   сейчас захардкожены светлые цвета (`#E8EEF2`/`#8A959D`, белый фон
   неотмеченного чекбокса) — в тёмной и контрастной темах не меняются.
   Если disabled — это правило «непрозрачность 40 %», его нужно применить и
   к этим контролам; иначе нужны пары «токен × состояние». Отдельная
   задача, не блокирует палитру.
6. **Дробный масштаб экрана** (125/150 %, зум браузера): тонкие линии
   сетки разной светлости, заливки «наезжают» на соседнюю колонку. Не
   связано с палитрой, вынесено в отдельную задачу.

# Часть 2. Карта кода и механики

Таблица TableCanvas → обёртка TableGlide → Glide Data Grid
(`@glideappsfinal/glide-data-grid`, canvas-рендер, наш форк). Пути ниже —
от корня библиотеки.

## Как устроена интеграция палитры

- `generators/table-token-states/` — пакет дизайнера v1.2 без изменений
  (`code/`, `docs/`, `demo/`). Источник истины, не правится.
- `generators/table-token-states/emit-table-colors.ts` — слой интеграции:
  `buildTableColors()` → временные значения для недостающих токенов (их
  состояния считаются той же `fillStates`, не руками) → записывает
  `packages/ui-kit/src/components/TableGlide/theming/table-colors.generated.ts`
  (60 ключей × 6 тем, готовые непрозрачные цвета + `TABLE_FILL_PARAMS` —
  параметры формулы по темам для расчёта в рантайме).
- `theming/fill-states.ts` — копия той части формулы, что считает заливки
  (OKLCH, шаг по лучу, hover2, наложение выделения), + кэш по
  `${тема}/${hex}`. Совпадение с генератором закреплено тестом
  `fill-states.test.ts` (бит в бит против палитры, все 6 тем).
- `generators/table-content-tokens/` → `TableGlide/content-tokens.generated.ts` —
  отдельный генератор цветов содержимого ячеек (текст, бейджи, кнопки,
  цвета данных): читает темы атомарной команды из node_modules (6 тем).
  Список нужных цветов и где их искать — `lib/token-map.js`; в
  `report.md` — цвета, взятые не напрямую из своей темы, и что поменялось
  у атомарной команды с прошлого запуска. Запускается в конце
  `npm run update` / `updateX`.

## Как цвет попадает в ячейку (рендер + обёртка)

Рендер: заливка ячейки — конвейер в
`packages/core/src/internal/data-grid/render/data-grid-render.cells.ts`
(репозиторий форка): `bgCell` из объединённой темы ячейки → если ячейка в
выделении, накладывается `theme.accentLight` → поверх highlightRegions.
`blend()` для непрозрачного цвета возвращает его как есть, поэтому
готовые цвета не смешиваются, а подставляются.

Механизм состояний в обёртке:

- **Ячейка со своим цветом**: `TableGlide.tsx`, `getCellContentGlide`:
  `theming/cell-fill-override.ts` кладёт в тему ячейки `bgCell` =
  rest|hover (в выбранной строке hover|hover2) и `accentLight` =
  active|hoverActive. Для цветов потребителя (`columnThemeOverride →
bgCell`) состояния считает `getCellFillStates(hex, theme)` с кэшем.
- **Выбранная строка** (`highlightActiveType='row'`): фон строки отдаёт
  тема строки (`getRowThemeOverride`, лестница — `resolveActiveRowBg` в
  `cell-fill-override.ts`), регионами не красится. Активная ячейка при
  одиночном выделении не тонируется: в её тему кладётся
  `accentLight = bgCell` (`soloActiveCellOverride` в `getCellContentGlide`) —
  остаётся рамка. Своя заливка одиночной ячейки в режиме `cell` тоже не
  рисуется (`highlightActiveRow` в `useBaseHighlightRegions`).
- **Hover внутри выделения** (обычные ячейки): `getRowThemeOverride` —
  строка под курсором отдаёт `accentLight: selectionActiveHoveredBg`;
  отмеченные чекбоксом строки — свои active/hoverActive-варианты.
- **Выделение колонок (Ctrl-мультивыбор) и строк по нумерации** —
  собственные оси обёртки (не выделение glide), рисуются регионами
  (`hooks/selection/useColumnRowHighlightRegions.ts`) со стилем
  **`style: 'accent'`** (доработка рендера): заливка берёт `accentLight`
  из темы ячейки — тот же механизм, что у обычного выделения.
- **Выделенная шапка**: `columnsForRender` — `bgHeader/bgHeaderHasFocus =
selectionServiceActiveBg`, `bgHeaderHovered = bgHeaderSelectedHovered`;
  группа — `getGroupDetails` (`bgGroupHeaderHovered`).
- **Доработки рендера**: стиль региона `'accent'` и
  `Highlight.drawAboveSelection` (обводка второй фазой поверх рамки
  выделения, включая канву шапки). Рамки ошибок помечены
  `drawAboveSelection: true` (`useBaseHighlightRegions.ts`) — рисуются
  поверх любого выделения.

Порядок слоёв окраски целиком — комментарий в
`hooks/selection/useColoringLayers.ts`; карта подсистемы выделения —
`hooks/selection/README.md`.

## Не подключено / известные ограничения

- `editedSuccessfullyCell*` (5 ключей) — canvas-реализации нет; сохранённая
  ячейка красится только CSS-слоем TableCanvas
  (`TableCanvas/styles/cellStyle.ts`, класс `rdg-edited-successfully-cell`).
- Объединённые ячейки: hover-вариант цвета только при курсоре на главной
  строке блока (ячейки блока передают отрисовку главной —
  `getCellContentGlide`, `findBlockOrigin`). По ответу дизайнера v1.2 — пока
  не менять.
- Свой цвет потребителя (`columnThemeOverride.bgCell`) таблица не
  перекрашивает под тему: фиксированный светлый hex в тёмной теме останется
  светлым. Для статусов нужно брать цвета темы (`theme.bgCellPositive` и
  т. п.) — так сделано на стенде ColoringStates.
- `fadeWhite`/`fadeGray` — в палитре есть, не используются.
- `checkboxVisibleRowIndexes` — @deprecated (на цвет больше не влияет).
- High contrast light: `TABLE_FILL_PARAMS.primaryHex = null` → у серых
  цветов потребителя нет hover в этой теме (ждём токен от владельцев темы).

Задачи, которые сознательно не вошли в интеграцию палитры, — `BACKLOG.md`.
