форк glide `feature/table-theme-states` (репо RamK-16/glide).

Документ в двух частях: **часть 1 — для дизайнера** (без кода, с объяснением

# Часть 1. Для дизайнера

## Коротко: что уже работает

Мы интегрировали твой генератор целиком. Все 53 цвета таблицы теперь берутся
из палитры «семантический токен × состояние», по всем шести темам, включая
настоящую тёмную (раньше тёмной темы у таблицы фактически не было — она
красилась светлыми цветами). Работают по твоей модели:

- **покой / hover / выделение / hover-внутри-выделения** для обычных ячеек;
- **ячейки со своим цветом** (жёлтые редактируемые, статусные
  positive/negative/warning/info, произвольные цвета потребителя) во всех
  четырёх состояниях: в выделении они показывают наложение на свой цвет,
  при hover — свой шаг «+1δ», ровно как в твоём прототипе;
- все способы выделения: диапазон мышью, колонка кликом по шапке
  (включая Ctrl-мультивыбор), строка кликом по нумерации;
- отмеченные чекбоксом строки и их пересечения с выделением и hover;
- шесть тем, временные значения для дыр (data-yellow-light и др.) подставлены
  и помечены.

Для проверки собран стенд в Storybook: таблица со всеми типами ячеек,
переключатели всех режимов и тем (Storybook → Локальные компоненты →
TableCanvas → ColoringStates).

## Проблема 1 (главная): подсветка строки активной ячейки

**Что это за состояние.** В таблице есть режим: пользователь кликает по любой
ячейке — и **вся строка этой ячейки подсвечивается** голубым (у нас этот режим
называется `highlightActiveType='row'`). Это НЕ выделение диапазона и НЕ
отметка чекбоксом — это именно «строка, в которой находится активная ячейка».
В твоём интерактивном прототипе (table-states-prototype.html) это поведение
есть: выбираешь ячейку → строка подсвечивается.

**Как это ведёт себя у тебя в прототипе.** Подсветка строки — «живое»
состояние, как выделение:
- цветные ячейки в подсвеченной строке (жёлтая редактируемая, зелёная/красная
  статусная) не закрашиваются сплошным голубым — они показывают **наложение
  на свой цвет** (приглушённый жёлто-голубой и т.п.);
- при **наведении мыши** на подсвеченную строку её цвет **углубляется**
  (становится темнее/насыщеннее).

**Как это ведёт себя у нас сейчас.** Подсветка строки — верхний непрозрачный
слой: вся строка заливается сплошным цветом (светло-голубым
`surface-accent-minor`, а если у строки есть чекбокс — его active-вариантом),
**поверх** цветных ячеек. Жёлтые и статусные ячейки под подсветкой просто
исчезают. Hover с подсветкой никак не взаимодействует.

**Почему мы это не починили сами.** В твоей карте `TABLE_COLORS` (53 ключа)
**нет ключей для этого состояния** — мы не знаем, какие пары «токен ×
состояние» ты в него закладывала. Механизм у нас уже готов (точно так же мы
починили чекбокс-строки и все виды выделения) — нужна только спецификация.

**Что нужно от тебя** — такие же пары «ключ → токен × состояние», как в
разделе 2 твоего table-token-sources.md, для состояния «строка активной
ячейки»:

| Что красим | Вопрос |
|---|---|
| Фон обычной ячейки в подсвеченной строке | какой токен × состояние? (сейчас: surface-accent-minor × rest, как отмеченная строка — верно?) |
| То же под курсором (hover) | токен × состояние? (hover? hoverActive?) |
| Цветная ячейка (редактируемая/статусная) в подсвеченной строке | наложение выделения на её цвет, т.е. её «active»? |
| То же под курсором | её «hoverActive»? |
| Если строка одновременно отмечена чекбоксом | что побеждает / как складывается? |
| Сервисная зона (нумерация/чекбокс) этой строки | токен × состояние? |

## Проблема 2: выделенная шапка под курсором

В твоём README («Как подключить», п. 5) сказано: у выделенной шапки вместе с
фоном `selectionServiceActiveBg` должен ставиться hover-вариант
`bgHeaderSelectedHovered`, и то же для групповой шапки. Эти два цвета
(`bgHeaderSelectedHovered`, `selectionServiceActiveHoveredBg`) мы в палитру
положили, но **в таблицу ещё не подключили** — сейчас выделенная шапка при
наведении не меняется. Подключим без вопросов — просто подтверди, что пары
из п. 5 актуальны (это наш долг, не твой).

## Проблема 3: объединённые (merged) ячейки

В таблице ячейки могут объединяться в блоки (по колонкам и по строкам).
В твоей модели объединённых ячеек нет. Сейчас у нас:
- блок в выделении красится **полосами по пересечению** с выделением
  (попала половина блока — красится половина), цвета берутся правильные;
- hover-вариант цвета блока срабатывает только когда курсор на «главной»
  (верхней левой) строке блока — техническое ограничение.

Вопросы: hover части блока должен красить **весь блок** или только
пересечение? Частичное попадание блока в выделение — красить блок целиком
или полосой по пересечению (как сейчас)?

## Проблема 4: рамка ошибки и рамка выделения (у нас, в работе)

Ячейка с ошибкой имеет красную рамку. По прототипу красная рамка должна
рисоваться **поверх** синей рамки выделения всегда. У нас она пока местами
перекрывается синей — это наш баг отрисовки, чиним, вопросов к тебе нет.
Упоминаем, чтобы ты не считала это намеренным поведением.

# Часть 2. Для Claude-агента дизайнера (карта кода и механики)

Контекст: dais-ui — библиотека React-компонентов; таблица TableCanvas →
обёртка TableGlide → форк Glide Data Grid (canvas-рендер,
`@glideappsfinal/glide-data-grid`, репо RamK-16/glide). Все пути ниже — от
корня dais-ui, пути форка — от корня репо glide.

## Как устроена интеграция палитры

- `generators/table-token-states/` — пакет дизайнера 1-в-1 (code/, docs/,
  demo/). Источник истины не правится.
- `generators/table-token-states/emit-table-colors.ts` — слой интеграции:
  `buildTableColors()` → + временные значения для null-дыр (их состояния
  считаются той же `fillStates`, не руками) → эмитит
  `packages/ui-kit/src/components/TableGlide/theming/table-colors.generated.ts`
  (53 ключа × 6 тем, непрозрачные hex + `TABLE_FILL_PARAMS` — параметры
  формулы по темам для рантайма).
- `theming/fill-states.ts` — контролируемая копия fill-пути формулы
  (OKLCH, шаг по лучу, наложение выделения) + кэш по `${тема}/${hex}`.
  Эквивалентность генератору закреплена тестом `fill-states.test.ts`
  (бит-в-бит против палитры).
- `theming/theme-tokens.generated.ts` + `generators/theme-tokens/` — отдельный
  генератор «чернил» (текст/бейджи/кнопки в ячейках): парсит CSS-переменные
  тем атомарки прямо из node_modules (6 тем), карта алиасов имён — `MAPPING`
  в `generate-theme-tokens.js`, спорные пины — `report.md`.

## Ключевая механика состояний (форк + обёртка)

Форк: заливка ячейки — конвейер в
`packages/core/src/internal/data-grid/render/data-grid-render.cells.ts`
(~стр. 556–640): bgCell → (rowDisabled) → **accent-петля**: при
`accentCount > 0` (ячейка в выделении) блендится `theme.accentLight`, где
`theme` — **полностью смерженная per-cell тема** (включая
`cell.themeOverride` и `getRowThemeOverride`) → highlightRegions.
`blend()` (`color-parser.ts`) для непрозрачного hex возвращает цвет как есть —
поэтому предвычисленные непрозрачные цвета не смешиваются, а подставляются.

Отсюда весь механизм состояний:

- **Ячейка со своим цветом**: `TableGlide.tsx`, `getCellContentGlide`
  (~стр. 700): через `theming/cell-fill-override.ts` в per-cell
  `themeOverride` кладётся `bgCell` = rest|hover и `accentLight` =
  active|hoverActive. Нативное выделение форка само подставит accentLight
  ровно когда ячейка в выделении. Для потребительских цветов
  (`columnThemeOverride → bgCell`) состояния считает
  `getCellFillStates(hex, theme)` с кэшем.
- **Hover внутри выделения** (обычные ячейки): `TableGlide.tsx`,
  `getRowThemeOverride` (~стр. 1440): hovered-строка отдаёт
  `accentLight: selectionActiveHoveredBg`; чекбокс-строки — свои
  active/hoverActive-варианты.
- **Выделение колонок (Ctrl-мультивыбор) и строк по нумерации** — собственные
  оси обёртки (не glide-selection), рисуются регионами:
  `hooks/selection/useColumnRowHighlightRegions.ts`. Их заливки переведены на
  новый стиль региона **`style: 'accent'`** (патч форка): заливка такого
  региона берёт `accentLight` из per-cell темы — тот же механизм, что натив.
- **Патч форка** (ветка feature/table-theme-states в RamK-16/glide):
  `Highlight.style 'accent'` + `Highlight.drawAboveSelection` (обводка
  второй фазой поверх нативной рамки; поле пробрасывается через ремап
  highlightRegions в `data-editor.tsx` ~стр. 1332 — при пересборке объектов
  оно терялось). Файлы: `data-grid-render.cells.ts`,
  `data-grid.render.rings.ts` (параметр `phase`), `data-grid-render.ts`
  (вторая фаза в трёх местах отрисовки).

## Проблема 1 в терминах кода (highlightActiveType='row')

Подсветка строки активной ячейки строится в
`hooks/selection/useColumnRowHighlightRegions.ts` (блок `activeRow`,
~стр. 160–185): пушится регион `style: 'no-outline'` с **непрозрачным**
`selectionCheckboxBg` (или `selectionActiveCheckboxBg`, если у строки есть
чекбокс) по зоне данных, с вырезом под текущий selection-диапазон. В форке
регионы блендятся ПОСЛЕ per-cell заливок → непрозрачный регион перекрывает
цветные ячейки; hover не участвует (цвет региона статичен).

Готовое решение (ждёт только токенов от дизайнера): убрать непрозрачный
регион и перевести подсветку на row-тему — `getRowThemeOverride` для
activeRow отдаёт `bgCell` (фон строки) + `accentLight`
(active-вариант) — тогда cell-override цветных ячеек победит фон строки, а
hover подключится как у чекбокс-строк. Нужные ключи — из ответа на вопросы
части 1 (таблица в «Проблеме 1»); вероятно это новые ключи палитры вида
`activeRowBg / activeRowHoveredBg / activeRowCheckbox…` — тогда добавить их
в `TABLE_COLORS` генератора и перегенерить.

## Не подключено / known issues (код)

- `bgHeaderSelectedHovered`, `selectionServiceActiveHoveredBg` — есть в
  палитре, не потребляются. Точка подключения: `TableGlide.tsx`
  `columnsForRender` (~стр. 447: сейчас `bgHeader/bgHeaderHasFocus =
  selectionServiceActiveBg`, добавить `bgHeaderHovered`) и `getGroupDetails`
  для групповых шапок.
- `editedSuccessfullyCell*` (4 ключа) — canvas-реализации нет; сейчас
  сохранённая ячейка красится только CSS-слоем TableCanvas
  (`TableCanvas/styles/cellStyle.ts`, класс `rdg-edited-successfully-cell`).
- Merged-ячейки: hover-вариант только при курсоре на origin-строке — ячейки
  блока делегируются к origin (`getCellContentGlide`, `findBlockOrigin`),
  и `rowHover` сравнивается с origin-строкой.
- Z-порядок рамки ошибки: регионы ошибок помечены
  `drawAboveSelection: true` (`useBaseHighlightRegions.ts`), верхняя фаза
  отрисовки в форке реализована, но в теле таблицы рамка местами всё ещё
  перекрывается синей — в активной отладке (следы: пребандл содержит патч,
  `highlightAboveRedraw` в трёх путях отрисовки; отдельно починен
  overlay-канвас шапки, который съедал верхнюю линию рамки первой строки).
- `fadeWhite`/`fadeGray` — в палитре есть, не потребляются.
